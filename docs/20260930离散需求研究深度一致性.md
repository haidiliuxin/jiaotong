# 离散需求研究深度一致性

零调用预检发现：原话“检验同一停车措施在小汽车需求系数0.9和1.0下是否稳健”已正确冻结 `[0.9,1.0]` 和四场景上限，但研究深度仍被标为 `adaptive`，没有形成明确的逐需求检验义务。改成“需求变化下是否仍有效”才会触发，说明两个入口判定不一致。

研究深度现复用已验证的离散需求系数提取器：用户明确给出两个以上离散点时，冻结 `demand_robustness` 与逐需求检验义务；只给 `1.0` 不触发。若又明确要求不做需求检验，预检直接报告冲突，避免同一任务一边运行多需求、一边按单需求结束。位置、方向和具体措施仍由模型在观测后选择。

原话的无密钥预检返回 `demand_factors=[0.9,1.0]`、`total_runs=4`、`research_depth=demand_robustness`，没有发出模型请求或启动原生场景。RC5 原记录不能转记为新版通过。

后续 RC8 真实任务已证实 `research-depth-v2` 使该原句完成双需求各自新基准和同一停车治理的四个配对场景；最终结论因旧 v7 否定句误拒绝而使整项仍为 `incomplete`，详见[RC8 实测](20260930RC8双需求实测与否定证明v8.md)。
