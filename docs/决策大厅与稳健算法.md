## 新算法：先满足约束，再比较最差情况

原实验通常先给出基准需求推荐，再评估它在额外需求下的适用性。新增分析将所有已经测试的相同措施分组，在设定的全部需求下比较其最差表现。

1. **按实际措施分组。** 用完整参数内容识别措施，而不是从场景名称猜测。相同修改集合的排列顺序不影响识别；不同治理范围或强度不会合并。
2. **严格需求配对。** 每个措施必须在任务预设的每个需求系数下具有执行完成且产生指标的场景，并有相同需求的无治理基准。缺少实验不插值，未完成输出不参与。
3. **先满足原实验约束。** 每个需求都必须通过已经保存的原约束评估；新增分析不放宽阈值，也不重新解释禁行、禁转响应。相同措施或基准的重复结果不一致时，不能选其中最好的结果。
4. **计算最差代价。** 对合格措施计算三个量：最差全网耗时增幅、最差邻区耗时增幅、最大的邻区新增过饱和有向里程。第三项是新增总量，不是净增量。
5. **给出权衡前沿与稳健建议。** 如果另一措施三项代价均不高且至少一项更低，则该措施被其支配。保留未被支配措施，按最差全网增幅、最差邻区增幅、新增过饱和里程依次最小化；完全并列时按修改条数、名称确定稳定次序。

其中，全网耗时增幅为：

```text
r(p,d) = 100 × [T(措施p, 需求d) / T(无治理, 需求d) − 1]
最差全网增幅 = max_d r(p,d)
```

负值表示耗时下降。“最差”取最大值，因此-0.1%比-2%更差。没有用平均值或人为加权评分抵消某个需求的失败。比较前将目标值统一保留9位小数，避免浮点噪声及成对容差造成循环支配；显示仍保留原计算值。

仅在整个任务完成且至少设置两个需求系数时给出跨需求建议。即使通过，也仅限已经测试的需求点。该分析为新增的确定性决策方法，不是大模型预测，不声称找到所有可能措施中的全局最优，也不声称原生交通分配算法更快或更准确。

原始 `state.json`、推荐、模型输入输出和封存证据不会被重写。CLI可独立复算，输出JSON而不运行TranStar：


## 新算法：空间代价分解

地图按每条有效有向道路计算：

```text
ΔT_i = L_i × (q_方案 / v_方案 − q_基准 / v_基准)
增加耗时 = Σ max(ΔT_i, 0)
节省耗时 = Σ max(−ΔT_i, 0)
全网净变化 = 增加耗时 − 节省耗时
```

热点按正的ΔT降序展示，支持点击回到同一有向路段。改善路段单独排序，新增过饱和长度单独累计。这样一处改善不会掩盖另一处的代价增加。耗时变化包含车流重新分配，不等同于该道路的拥堵成因，也不是完整出行时间或全部节点延误。
