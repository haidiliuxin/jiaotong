# 面向停车干扰治理与需求条件调整的交通仿真智能体

面向评审的集中整理版本见[参赛研究报告](../成果/参赛研究报告.md)。本文保留开发过程及按发生顺序追加的诊断结果；各阶段的“尚未完成”须结合后续独立核验记录阅读，不作为当前能力状态的唯一依据。

版本：2026年9月8日开发初稿，补充等预算对照和模型诊断。当前报告覆盖已核验实验，不是最终参赛定稿。

## 摘要

本项目基于赛事提供的南京案例及国产TranStar城市交通版，构建“问题输入—任务与规则校验—新基准仿真—瓶颈筛选—候选治理—真实工具调用—指标比较—反馈调整—解释输出”的交通仿真智能体。核心程序采用规则推理、带来源的知识条目和确定性工具接口，既可从命令行独立运行，也可通过本地网页交互，不依赖大语言模型服务。

首个区域任务完成10个真实场景、70次模型模块调用，包含新基准、两种治理强度、同输入重复、两个需求水平的匹配基准与治理对比，以及两次由不利结果触发的缩小范围实验。核心区加权速度在基准需求下由12.07提高至26.85km/h，但原推荐不能在所有需求水平下满足邻区约束。智能体进一步将0.9和1.1倍小汽车需求下的治理缩小至单路段，得到分别满足既定约束的条件建议。结果表明，本原型的价值包括识别方案适用边界，而不只是寻找更大的局部改善幅度。

另完成11场景、77次模块调用的等候选预算对照：每策略每个需求点均试验两项候选，0.9和1.1倍需求下固定强度搜索退回基准，反馈搜索通过缩小范围获得合格方案；1.0倍下两者建议一致。第二轮决定在其仿真之前保存并通过独立核验。

所有效果仅针对赛事调整后的仿真案例，不代表南京真实交通状况。尚未完成现实标定、有效微循环转向与组合措施。已保存已有实验复核、实际新建四场景任务和同任务完成的三段真实浏览器录像，中间计算等待明确省略。

## 研究问题、数据与模型

研究问题是：在不新增道路、维持主实验各类需求和分配配置一致的条件下，如何识别可能受停车干扰影响的区域瓶颈，用有限数量的治理路段改善运行，并在需求变化及周边约束下调整推荐？

源案例位于 `南京市案例数据库/南京案例/基础路网`。全网GEOM含32,981条有向记录；评价集合按道路类别1至6、正机动车车道和正长度固定为32,060条。案例含332个交通小区，主实验沿用既有OD。当前模型采用5次多路径增量加载，公交车辆按既有线路分配；不是均衡收敛证明，也不是逐秒微观仿真。

智能体根据新基准的道路类型、停车类别、速度、软件V/C、有效流量和长度筛选候选，再限制自动治理范围为种子路段邻域。首次任务选中：

| --- | --- | ---: | ---: |
| 七东线 | 3244→3245 | 1.143 | 3 |
| 七东线 | 3245→3244 | 1.143 | 3 |
| 长江村路 | 3240→3239 | 0.528 | 3 |

固定核心区共3条有向路段、2.814km；相邻影响区是有效机动车网络上的无向两跳节点范围内道路，排除核心区，共39条。后续缩小治理范围时，评价仍使用原3条核心路段和39条邻区道路，避免通过改变评价集合制造改善。

## 智能体技术路线与约束

任务卡承载道路、路段数、仿真总预算、主实验反馈次数和影响区阈值。知识库按任务场景筛选手册字段、指标定义与已验证经验，并保留来源。确定性工具负责文件编辑、模型启动、指标运算和约束检查，规则控制器根据真实结果决定下一次工具参数。

真实调用链为道路预处理、公交预处理、管理预处理、机动车分配、路段交通负荷、节点交通负荷和节点排队延误，共七个原有软件模块。程序在独立运行环境中串行执行，每个场景都从源案例复制；仅开放停车字段与显式小汽车OD系数，保留其他输入编码和字节。

运行前清除新工作副本中的指定评价输出，运行后检查进程退出、错误标志、新输出生成、数值有限性、路段行数、输入一致性与需求矩阵响应。日志记录时间、模块、进程、原始输出和参数差异。进程退出码为零不能单独作为实验成功依据。

本次在运行之前固定以下约束：邻区行驶时间增幅不超过0.5%，全网不超过0.1%，邻区新增过饱和有向里程不超过0.1km，固定核心区行驶时间必须改善。新增过饱和里程按新增总量计算，不用其他道路退出过饱和后的减少量抵消。候选通过约束后优先选择全网路段行驶时间消耗较低者；无合格候选则保留基准。上述阈值为实验假设，尚非现实管理标准。

## 评价口径

- 加权速度：Σ(qL)/Σ(qL/v)，单位km/h。
- 过饱和有向里程：Σ[L×I(软件V/C>1)]，单位km。
- 路段行驶时间消耗：1小时窗口的Σ(qL/v)，单位pcu·h，用于补充效率和邻区代价比较。

其中q为pcu/h、L为km、v为km/h。管理修正容量另从 `CapLinkVehMan.dat` 读取，不能与软件V/C分母混用。基准中44条有效路段的TimeLink达到极大值，因此不对其全网合计作总旅行时间解释。上述行驶时间消耗未独立囊括全部节点延误。

## 主实验与反馈结果

停车类别3先调整至2级；首轮通过约束，但核心速度与管理修正负荷仍提示改进空间，智能体追加1级治理。类别是离散参数，不能解释为“等级下降多少就提高相同比例容量”。

| 指标 | 基准 | 首轮2级治理 | 反馈1级治理 |
| --- | ---: | ---: | ---: |
| 核心区加权速度 km/h | 12.0747 | 20.7038 | 26.8502 |
| 核心区行驶时间消耗 pcu·h | 361.64 | 217.47 | 169.87 |
| 核心区过饱和有向里程 km | 2.814 | 2.814 | 2.814 |
| 全网行驶时间消耗 pcu·h | 227328.25 | 227168.53 | 227121.13 |
| 全网过饱和有向里程 km | 1608.6958 | 1609.2798 | 1609.2798 |

1级治理的核心速度提高约122.37%，核心行驶时间消耗下降约53.03%，但全网行驶时间消耗仅下降约0.0911%，且全网过饱和里程增加0.584km。三条核心道路的软件V/C仍超过1，不能把速度提高写成拥堵已消除。全网里程增加未作为本次既定硬约束，仍在报告中完整披露；正式研究应分析受影响位置和阈值敏感性。

## 需求敏感性与条件反馈

额外需求仅缩放小汽车OD至0.9和1.1，其他车型及公交设置保持不变。每个系数重新运行无治理与相同治理场景，所有效果相对各自需求基准计算。后续多路径探针在实际分配进程期间只读采集到5/15、4/15、3/15、2/15、1/15的五阶段OD权重，合计1.0；最终缓存的1/15代表末轮，不能解释为全程仅加载1/15需求。该采样不是逐OD累计路径流量守恒的证明，完整证据见[禁转联动诊断](禁转联动诊断.md)。

原3路段强治理在两个需求水平下均未通过全部约束。0.9倍需求时邻区新增过饱和0.287km；1.1倍时新增0.383km，并超过邻区行驶时间增幅上限。智能体利用剩余两次预算，分别将治理范围缩小到七东线3244→3245，其他两个核心方向保留原始类别。

| 小汽车OD系数 | 调整后的治理范围 | 核心行驶时间变化 | 邻区行驶时间变化 | 邻区新增过饱和km | 判定 |
| --- | --- | ---: | ---: | ---: | --- |
| 0.9 | 单路段1级治理 | −45.4847% | +0.0025% | 0 | 通过 |
| 1.0 | 原3路段1级治理 | −53.0271% | −0.5040% | 0 | 通过 |
| 1.1 | 单路段1级治理 | −33.9840% | +0.0041% | 0 | 通过 |

调整牺牲了部分局部收益，换取了既定邻区约束的满足。结论是三个已测离散需求条件下的建议，不是0.9至1.1之间所有需求都已经验证，更不能宣称同一个方案始终最优。

## 复现和智能体参与证据

实验目录：[20260908_031854_677ea5](../智能体实验/jobs/20260908_031854_677ea5/)。[独立核验文件](../智能体实验/jobs/20260908_031854_677ea5/verification.json)确认10场景、70模块执行完成，输入差异符合白名单，保存的输出与记录一致。重复基准的4类数组各32,981项逐项相等；确定性重复不当作独立统计样本。

首次开发运行由 `run` 完成8个场景，在发现需求失败后补充敏感性回退模块，用 `adapt` 校验已完成记录再追加2个场景。当前版本已将该回退阶段纳入默认 `run`。本轮真实证据是上述两次命令的连续实验，不声称最初旧版本单次命令已经包含新增功能。18项自动检查包含整个控制器在10次预算内完成主实验、复现、敏感性与双条件回退的路径。

反馈贡献主要表现为：从首轮结果触发强度加测；识别原推荐在需求变化下的约束违例；缩小范围并重新核验。上述首次开发实验的首轮与反馈实验计算次数不同；下一节使用独立的等预算协议补充可比性，不能用前一实验额外候选的收益替换后者结果。

## 相同候选预算下的策略比较

冻结原3条核心路段、39条邻区及全部评价阈值。每个需求点重新生成基准，两种策略共享3路段2级首轮；固定策略第二轮始终采用3路段1级，反馈策略只观察首轮，按约束与收益增强或缩小范围。每个策略每需求最多2项治理候选；本次都用满2项。相同候选只执行一次并共享结果，各策略分别计一次逻辑评估，不能当作独立随机重复。

| 小汽车OD系数 | 固定策略最终建议 | 反馈策略最终建议 | 固定/反馈核心时间变化 | 固定/反馈全网时间变化 |
| ---: | --- | --- | ---: | ---: |
| 0.9 | 基准 | 单路段2级 | 0 / −35.2550% | 0 / −0.044213% |
| 1.0 | 3路段1级 | 3路段1级 | −53.0271% / −53.0271% | −0.091111% / −0.091111% |
| 1.1 | 基准 | 单路段2级 | 0 / −24.2270% | 0 / −0.036858% |

0.9与1.1倍下反馈建议的邻区时间分别增加0.0021%和0.0031%，邻区新增过饱和里程均为0；均满足预设约束。1.0倍两者采用相同候选，收益与代价完全相同。这说明在这个固定案例上，根据首轮外溢缩小治理范围能在相同预算内找到固定强度搜索遗漏的合格候选，并不证明在所有道路、需求或策略集合上占优。

## 区域迁移：环洲路的外溢与反馈

按已完成新基准的候选排名，选择第二位、尚未研究的环洲路，只改变任务中的道路约束，保留原筛选、评价阈值及控制器。任务`20260908_053733_fe5765`完成4场景28次模块调用，核心3条有向路段、邻区41条；独立核验与四类数组逐项一致的基准复跑均通过。

首轮3路段2级治理使核心行驶时间下降15.9074%，但邻区时间增加1.1261%且新增过饱和里程超限。智能体在第二轮运行之前决定只治理3118→3117，反馈方案核心加权速度由9.0000变为10.0941km/h、核心行驶时间下降9.4714%，邻区时间下降0.0037%，通过原预设约束。全网行驶时间下降0.01633%，但全网过饱和里程增加0.631km，核心过饱和里程仍为2.146km，不能称拥堵消除。

剩余1次预算留给复跑，没有执行规则提出的更强1级候选。本任务未测试额外需求水平。561条可完整评价公交线路的补充运行时间审计没有变化，93条仍因数据条件排除。实验支持在另一道路范围上复用闭环流程，不证明所有区域可迁移。具体选区依据、参数、图表和日志见[区域迁移验证](区域迁移验证.md)。
