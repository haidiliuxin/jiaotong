## 已实现

大模型入口仍然只需自然语言，不需要选择场景。`natural-strategy-plan-v2` 让模型提出研究目标、待验证假设、所需证据、备选方向及采用／暂缓理由，并排序最多五组研究。执行器补全每组的真实步骤、需求条件、对照矩阵、最低预算、反馈预留、验收门槛和失败处理。右栏规划可展开为完整文档，实际结果返回后显示各组反馈。

一次任务只请求一次模型；工具权限、预算校验、动作执行、实测反馈和推荐由程序负责，执行与页面刷新不追加模型请求。程序补全的固定步骤不冒充模型推理，也不声称大模型在执行期间反复读取结果、重新决策。

| 研究类型 | 实际行为 |
| --- | --- |
| 路网体检 | 新增无治理原生流程。读取指定道路或全网全部参与分配路段，汇总道路耗时、过饱和路段与排名；不执行治理、不宣称收益 |
| 停车强度优化 | 停车2级起步，按既有实测反馈增强或缩小范围 |
| 单向组织对照 | 新基准、停车、单向、组合完整对照，保留公交、可达性和实际响应检查 |
| 路口禁转对照 | 使用已校验转向，计算新基准、停车、禁转、组合并核验四车型响应 |
| 需求压力检验 | 小汽车OD离散需求假设与成对基准；支持停车或已验证组合 |
| 跨需求稳健搜索 | 接入既有主动搜索与单路段失败回退；每个候选须预留完整需求验证，缺测不推定通过 |
| 邻区保护与回退 | 3跳邻区、全网毛新增过饱和上限0km；联合治理超限且预算足够时逐一实测入选方向 |

这是七种研究设计，底层治理动作仍为停车、单方向关闭、显式禁转。施工容量、信号配时、公交优先、分时错峰仍未接入执行；单向与禁转不联合执行。多道路可分组，各自基准和收益独立，不当成同步联合治理。

未指定需求时，模型可选择基础需求、±10%波动或+20%压力假设；只缩放小汽车OD，其他车型与公交保持原数据。明确需求系数或“不做敏感性”优先。默认总预算15次、最高30次；完整对照超预算则不执行。只诊断请求有单独权限检查。

白色工作台重做三列布局、地图工具条、两侧面板与底部指标栏。道路默认灰色，选中／核心路段用蓝色定位；速度、V/C、速度变化按需着色，保留双图对照。右栏分为规划、路网、评估、日志。诊断任务显示现状指标，不把零变化显示为治理改善。设置、档案、规则模式同步改为浅色；窄屏地图在上、面板在下。

## 已真实验证

本阶段 **2次线上模型调用，共6025 tokens**。没有轮询模型、自动重试、修改密钥或追加连接探针。

首次请求消耗2907 tokens。模型理解“两道路、仅体检、2次上限”，却把“不执行治理”误填到不支持能力字段，程序返回 `needs_validation`，未启动原生仿真。失败记录保留。随后将该字段改为能力枚举，禁止把计划说明填入阻塞字段。

修正后的一次请求消耗3118 tokens，模型自主安排红景路与长江村路两组体检。顺序运行2个新基准，合计14次原生模块调用；没有治理、需求缩放或复跑。两份任务分别从原始数组重算核验通过，各封存595个文件。
