# Git克隆后的实验档案核验

Git保留文件内容，但不保留本机运行时的修改时间。原严格核验还检查原生调用中的绝对场景路径，直接在另一个目录运行会拒绝。这些检查适合原运行目录，不能直接当作协作者克隆后的复核方法。

现在`verify_experiment.py`提供两种明确分开的核验方式。默认仍检查当前文件时间和当前绝对路径，未放宽原运行验收。原目录的严格核验通过后，可以保存带文件摘要、原时间戳和原运行根目录的档案清单；复制目录先逐文件核对内容，再用清单中的原时间和对应原路径重做模型输入、指标、响应、推荐及复跑检查。

## 原运行目录：建立可移植清单

```powershell
python scripts/verify_experiment.py 智能体实验/jobs/<任务编号> --seal
```

只在已停止写入、全部仿真完成的原目录执行。脚本先执行原有严格语义核验，成功后生成`archive_manifest.json`。清单包含任务内文件内容的SHA-256、字节数及原mtime，排除可重建的顶层私有`runtime/`、清单自身和复制侧核验输出；归档内的原生分轮证据仍覆盖。原始`state.json`、进程日志、参数、结果和绝对路径不重写。

图表或报告在封存后修改会被视为内容变化；如需更新，应在原目录再次严格核验并重新生成清单。该清单检查传输一致性，**不是数字签名，也不单独证明模型确实执行**；实际执行依据仍为原始进程与输入输出记录及语义复核。

## 协作者复制或克隆后

按README完成`git lfs pull`，确保下载的是实际二进制和媒体文件。在Windows、仓库根目录运行：

```powershell
python scripts/verify_experiment.py 智能体实验/jobs/20260908_051630_12acc1 --archive
```

`--archive`必须有该任务在原目录生成的清单。它先核对全部封存文件的内容，再重新计算指标、需求系数、输入差异和推荐约束。原生硬禁行或新禁转任务会在内容检查后核对原场景身份，不要求复制目录伪装成旧F盘位置。复制侧结果另存`portable_verification.json`，不覆盖原`verification.json`。不要在克隆目录通过重写原时间戳或修改日志来规避默认核验失败。

已封存并实际完成跨目录复核的任务包括停车`20260908_051630_12acc1`及显式禁转`20260908_100153_bb7198`。其他历史诊断脚本未因此自动获得可移植模式。
