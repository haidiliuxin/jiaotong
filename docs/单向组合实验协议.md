# 长江村路单向与停车组合实验协议

本协议在政策仿真前固定，配套任务卡为`examples/oneway_changjiang.json`。研究目标是比较有效执行的单向组织与停车治理，不能用红景路低流量响应试验代替拥堵治理结果。

## 分配配置与选点

使用随包Vehicle1分车型程序，Mparam635按已核对读取器派生，多路径增量5次、系数3.3。全部对照从原案例复制并使用这一配置，不与默认程序的历史结果交叉算收益。四类分车型Ljt/Rwm/volume及五类路段流量必须本次生成，未支持的机动车转向表从新副本移除。

固定要求长江村路3237→3236为待关闭方向。来源为已完成Vehicle1基准的前置筛选：394项瓶颈中第88项首个通过公交及全车型边界检查，q=1228.24 pcu/h、v=20.6 km/h、VC=1.86906。正式任务仍先运行全新基准，再复查瓶颈、反向停车及图约束；若不通过，不自动换路。

核心为3237→3236及反向3236→3237，邻区由新基准两跳一次性确定，全网为原有效机动车路段，之后各情景和需求水平保持同一范围。反向和待关闭方向原停车类别均为3。

## 完整情景与预算

| 场景 | 停车 | 机动车路权 |
| --- | --- | --- |
| S0 | 原值 | 原值 |
| S1_parking | 双向类别3→2 | 原值 |
| S2_oneway | 原值 | 3237→3236小汽车、摩托车、货车、公交码0→2；反向保留 |
| S3_combined | 双向类别3→2 | 与S2相同 |

需求为小汽车OD系数0.9、1.0、1.1；其他车型及公交线路不变。各系数完整测齐S0/S1/S2/S3，合计12场景，再复跑1.0无治理基准一次，共13场景、91次顶层模型调用。不是只把1.0获胜方案拿到其他需求测试。所有输入差异和同输入复现均核验。

## 评价及反馈

指标使用固定范围的ΣqL/v、加权速度、软件VC>1有向里程。候选须同时满足核心耗时改善、邻区耗时增幅≤0.5%、全网耗时增幅≤0.1%、邻区新增过饱和里程≤0.1km。另要求全网耗时严格改善，避免仅以关闭方向带来的核心流量减少推荐。

S2/S3还须核对ManageR1全部路权码、五类真实流量在禁行方向≤0.01、反向仍有车流以及同条件基准小汽车流量>1。零基准货车/公交不提供独立正流量归零证据；公交依靠原线路边保护。输入图证明不代表现实时段、执法、车道可实施条件。

每个需求下，先排除未通过响应或指标的候选，再选全网耗时最少者；同值优先较少改动，无合格候选则保留该需求基准。全部失败项、条件推荐和撤回原因保存。1.0主方案在其他需求下的合格性另行记录，不用条件换方案掩盖主方案不稳健。

三项政策是预先固定的完整组合，反馈表现为根据实测结果筛除和选择，不宣称此组实验本身证明自适应搜索或相同预算下的算法优越性。新增候选搜索需要另立实验记录。

## 命令与交付

```powershell
python -m traffic_agent oneway-trial --task examples/oneway_changjiang.json
```

协议设立时普通run/web保留能力门槛；后续v2完整验收已通过，现开放单方向禁行与停车组合。实验保存新基准选点、固定范围、政策前的`factorial_protocol.json`、完整13场景、参数差异、模块日志、真实响应、条件推荐、复跑及Markdown/HTML/CSV报告。完整结果核验后再更新研究报告和执行能力状态。
