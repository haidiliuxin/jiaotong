# 随包Vehicle1参数与车型阻抗读取依据

只读核对对象：`M6AssignVehicle1.exe`，x64 PE，85,504字节，SHA256 `5ea5b879b462a40bbe33ceb89b8fc23da1e286626946c22fe34ba651911e26a9`。本记录解释诊断参数的来源，不代表厂商发布过该参数文件或分支已经验收。

此前`20260908_054639_multipath_vehicle1_turn`因缺少`Mparam635.txt`失败，当时没有文件格式依据，未复制631代替。本次进一步核对读取器后才在新副本生成635，旧失败状态保持原样。

`Mparam635.txt`字符串位于虚拟地址`0x140010778`。打开文件后，`0x140003063`起先跳过两个标签行，读取第一个整数，再逐个跳过标签并读取数值。导入表`0x140010170`对应`basic_istream >> int`，`0x140010178`对应`>> double`，共七个整数加一个双精度数。变量使用关系如下。

| 顺序 | 全局变量地址 | 读取后用途 |
| --- | --- | --- |
| 1 | 0x140015bbc | 最短路分配开关 |
| 2 | 0x140015b1c | 最短路增量开关 |
| 3 | 0x140015b04 | 多路径分配开关 |
| 4 | 0x140015ac4 | 多路径增量开关 |
| 5 | 0x140015b90 | 最短路平衡开关 |
| 6 | 0x140015afc | 多路径平衡开关 |
| 7 | 0x140015af8 | 迭代次数，要求至少1 |
| 8 | 0x140015b98 | 误差标准，double |

六个开关在`0x140003217`起求和并要求为1。第四开关分支`0x1400032a0`读取`0x1400113f0`常数，实际为**3.3**，将第七字段保留为增量次数。相邻第二字段分支及迭代输出语句进一步佐证位置。此顺序与现有631八字段一致，故诊断保留标签与数值，只把首行文件名改为635；数值固定`0,0,0,1,0,0,5,0.001`。

四种机动车`AsignParameter_*`的派生参数也须在配对双方预先从7.2改为3.3，避免执行期间程序改写输入而失去可比性。不是以默认程序的结果作治理基准，必须重新计算双方。所有新增与修改参数纳入输入差异白名单和执行期间不变性检查。

`0x140007293`及`0x1400072ae`分别构造`Ljt_`和`Rwm_`前缀，并拼接车型及`.dat`。同包NodeAssignModel从AsignParameter读取OD、Rwm与volume文件名。诊断对四种车型的Ljt、Rwm、volume增加本次新生成校验，不能借用继承的历史分配结果。

默认M6AssignVehicle另在`0x40ebf2`读取`TimeLink.tsd`，之后逐路段与`NdelayForAssign.dat`相加。本次单向负例中Ljt已变为极大阻抗而TimeLink及最终四数组未变，与统一阻抗路径的静态线索一致；这尚不是完整动态读取追踪。缓存排序错位假设已受到所有FT与输入码逐行对应、目标车型阻抗只在正确端点变化的反证。

所用命令及原始指令节选见[Vehicle1读取器节选](Vehicle1参数与阻抗读取.txt)。没有修改厂商二进制；只有明确选择`probe_oneway.py --vehicle1`才使用这一诊断适配，普通智能体入口保持原配置。
