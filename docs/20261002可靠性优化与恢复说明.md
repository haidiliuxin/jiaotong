## 本轮行为

| 问题 | 处理 |
| --- | --- |
| 超时清理的异常覆盖原始错误，跳过后续封存 | 结束进程、等待、安全恢复配置和最终封存分别处理；保留原始错误及其原因，额外记录清理阶段的错误 |
| 无法确认进程树结束后继续复用运行环境 | 原生启动前保存配置备份及恢复标记；不能确认退出时保留现场和标记，拒绝后续复用。全局锁也检查历史任务的私有桥接运行环境标记 |
| 一条历史记录损坏导致整个档案接口断开 | 正常记录继续返回；损坏状态及页面使用的嵌套数据标记“记录不可读”并禁用选择。详情和地图返回通用错误；事件日志的损坏行只读跳过并显示数量，保留合法数组及对象载荷。原文件不修改、不删除 |
| 配置损坏后无法通过设置页恢复 | 设置页仍可打开，显示恢复入口；明确点击“备份损坏配置并重置”后保留原字节、恢复默认配置并清除凭据，随后可重新保存。可读取的正常配置不能使用该入口 |
| 计算中途空间耗尽 | 启动检查、总任务调度和每次场景准备复检容量；普通场景按源文件×2、单向/显式禁转×8，加上新运行环境实际字节和512MiB预留估算。空间不足时停止新场景，不自动缩减预算 |
| 修改后缺少统一回归入口 | 新增 `scripts/run_offline_tests.py` 和GitHub Actions；分支push、PR及手动触发完整Python和4组Node回归。只检出必需源码和测试片段，不下载LFS、调用线上模型或启动原生仿真 |

磁盘倍率是保守工程估算，不能保证原生输出大小或防止其他进程随后占用空间。它不代表实测资源上限，也不会把一次需求测试升级为稳健性结论。

## 原生运行环境的人工恢复

发生不能确认进程树已退出、配置恢复失败或封存失败时，运行环境内保留 `agent_runtime_cleanup_required.json`。正常运行清理完成后会删除该标记。

1. 阅读标记中的 `manifest`、`cleanup` 和 `config_backup`，保留任务日志及失败原因。
2. 确认原进程树已经结束；仅凭PID不存在不能证明其子进程已结束，不能按可能复用的旧PID盲目结束进程。
3. 按 `config_backup` 将原始字节恢复至该运行环境的 `files/runinfo_vc6.txt`，核对日志和恢复结果。
4. 确认以上检查完成后移除该运行环境的恢复标记，再新建任务。不要覆盖旧任务或把旧失败改为成功。

私有单向/禁转运行环境位于对应任务目录内；其未完成清理也会阻止该实验输出根目录继续启动原生任务。系统不会自动删除标记或尝试用历史任务补齐预算。

## 配置恢复与凭据

重置仅用于损坏/不可读的设置。原文件备份为同一配置目录中的 `llm.corrupt-<随机编号>.json`；备份不进入实验目录或交接证据包，也不通过网页返回内容。正常密钥仍采用当前Windows用户DPAPI，不明文回退。备份或新设置写入失败时保留原文件，界面显示失败。

恢复读、保存和重置均不请求模型。设置页显示默认值时不表示已取得授权；重置后须重新保存正确服务及密钥。未保存输入、并发设置操作和重复连接测试仍由现有保护拦截。

## 验证及完整模型验收

统一离线检查命令（Python 3.12、Node 24）：

```powershell
py -3.12 scripts/run_offline_tests.py
```

运行器任一组失败即返回非零退出码，不跳过现有测试。CI使用经独立源码快照验证的稀疏检出范围，配置见[离线自动回归说明](离线自动回归说明.md)。GitHub上的实际运行状态须以Actions页面为准，本地通过不能替代远端执行结果。

真实模型验收仍因用户指定服务HTTP401未完成。本轮没有重置实际用户配置，也未再次请求失败配置或换用其他服务。有效授权保存后，按[仓库clone测试说明](20260930仓库clone异机测试说明.md)第4节的原文新建研究一次，再运行：

```powershell
py -3.12 scripts/verify_programme.py <总任务ID> --no-write
```

核对3场景、21个顶层模块、两区域同等级对照及最终复核；失败或缺测必须保留，不能用离线回归通过宣称完整验收通过。
