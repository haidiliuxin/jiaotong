# 结论引用 v9 与问题措辞 v4 复核

## 两个实际失败

RC10 包内的混合问题要求长江村路至少比较两个停车备选，再研究单向及组合。模型初始规划给出一组停车研究和一组单向研究，场景预算允许执行；但 H2 写成“至少一个停车候选在全部原定约束与控制响应检查中通过”。旧 `bounded-question-wording-v3` 只识别“通过……约束”，没有识别“约束……通过”，把已包含推荐资格的提问误判为单问控制响应。原尝试 `validation_failed`，1 次模型请求、7,097 tokens、0 原生场景。`bounded-question-wording-v4` 仅补这一语序的有界识别；同一封存提议只读复核由 1 项冲突变为 0 项，未改问题原话、量词、判据或原失败状态。

另一条 RC10 双需求任务在 0.9 与 1.0 下各执行新基准及同一停车1级治理，共 4 个真实 TranStar 场景、28 个顶层模块。两个需求的核心耗时分别下降 18.1156% 和 23.3087%，均通过冻结约束；0.9 邻区耗时仍增加 0.0280%，1.0 邻区耗时下降 0.1821%，两者毛新增过饱和均为 0 km。模型第一次最终回复及有界修正均将 1.0 的 `has_measured_cost` 误填为 `true`，与执行器记录的事实冲突。原 `measured-conclusion-v8` 正确拒绝，整项为 `incomplete`；不能由四次原生场景完成推出整项结论通过。该运行 4 次模型请求、54,633 已知 tokens。

## 实现与验证边界

`measured-conclusion-v9` 在最终复核工具中要求模型列出全部 `reviewed_cost_refs`；约束通过、正代价标记和里程继续由执行器从实测生成并校验，模型仍必须在公开文字中解释收益、周边代价和证据范围。旧 v1–v8 保留原 `cost_acknowledgments` 校验及提示词；跨组核验继续识别 v8。对封存失败回复只做字段影子转换，v9 校验无已检测冲突，原运行不重判。

对同一封存观测又进行 **1 次真实模型最终复核调用**：新回复使用 `reviewed_cost_refs`，校验 `accepted`，独立只读复核 `no_detected_conflict`，报告 16,480 tokens，**没有新增原生场景**。这验证了 v9 工具回复可用，仍不是 v9 的完整模型选择加原生执行闭环。632 项 Python 检查通过。对原四场景的模块清单、完成码、输出新鲜度、输入差异、范围指标和两项治理对照逐一只读重算一致；由于整项 `incomplete`，没有出具完整证明。

原件路径、SHA256、逐响应去重账目和边界见[验证记录](validation/20260930_v9_conclusion_and_v4_wording_evidence.json)。本次 6 次新增模型请求、78,210 已知 tokens；项目留存保守累计 **115 次／1,067,794 已知 tokens**，相对授权累计上限 684 次／4,132,560 tokens；不等于完整账户账单。下一步仍须用新版包做少量代表性完整任务验证，包括混合候选执行与最终结论，再做物理异机验收。
