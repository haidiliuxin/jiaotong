# 自然语言需求系数冻结

在计划双需求真实试验前，零调用预检发现“需求系数0.9和1.0”没有进入 `explicit_fields`：研究深度被识别为需求变化检验，但固定条件仍为 `[1.0]`。若直接请求模型，研究点可能与用户原话不一致。原件是预检返回值；没有启动模型或 TranStar。

## 已实现

规则入口与大模型入口共用需求系数提取器，支持原有冒号逗号写法，也支持“需求系数0.9和1.0”、“为0.9、1.0”、“分别为0.9与1.0”等明确离散点写法。提取只冻结用户写出的数字，不按问题类型猜测需求值；现有 `Task` 边界继续检查系数范围、包含 1.0、唯一性和最多三个点。区间写法当前不等同于离散点，直接提示用户列出实验点；与“不做敏感性”冲突时不悄悄覆盖。

## 离线验证

原任务句子的预检现返回 `demand_factors=[0.9,1.0]`、`repeat_baseline=false`、`total_runs=4`，研究深度为 `demand_robustness`；`model_requested=false`、`native_started=false`。规则入口、模型前置字段和旧模板使用同一结果。623 项 Python 检查通过。

## 真实验证与边界

当前还没有在本次源码上运行双需求模型与 TranStar 配对。只有真实完成每个需求的新基准、同一治理方案和全部结论复核，才可宣称该限定案例的稳健性检验完成。离散点不代表区间连续稳健，也不代表分时实况。
