右侧和报告分别列出控制响应、核心耗时、邻区门槛及推荐资格，场景链接可定位地图。新任务停止说明从实际完成记录生成，模型原解释可展开查看。结构化假设只能正式引用自身冻结检验，缺测保持未知；其他结果仍供模型讨论取舍。既有七场景只读回归通过，原任务语义结论仍needs_review。详见[假设引用与逐组实测清单](20260930假设引用范围与逐组实测清单.md)。

## 用自然语言发起研究

选择 **大模型自主规划**，在左侧输入地点、问题、目标及预算即可。无需先选场景。模型先提出假设和研究设计，通过本地预算、范围和工具权限检查后才执行。未知地点或缺少明确禁转目标时会要求补充；明确要求“自动找区域”时，可根据新基准在合法候选中选择。

输入示例（点击运行会产生新模型请求和真实仿真，不是离线演示）：

> 研究七东线停车治理。先读取新基准，再比较一个单方向的停车措施。需求系数1，最多治理2条，总预算2次仿真，不复跑。保留没有收益的结果和邻区代价。

更完整的混合研究可要求两条道路分别建立新基准，并在其中一组比较停车、单向及组合。最低场景数由实际设计核算：独立停车研究至少2次；单向与停车完整组合至少4次。扩大需求条件、比较等级或增加独立研究都会增加成本。新任务默认模型请求总预算为7次；初始规划至多修正一次，本组交接与最终复核共享一次修正，均计入这个上限，接口失败不会不断重试。历史6次任务仍按当时协议回放。

本组对照已齐、下一组选择合法、后续必需研究和最终复核仍有足够预算时，模型可针对交接解释或代价确认中的具体错误修正一次。原观测、门槛与所选下一组保持，模型重新提交并接受核对；不追加本组仿真。页面保留首次错误、修正状态和两次用量。余额不足、首次提议不完整或第二次仍失败时，研究保持未完成；不会跳过后续研究换取通过。

当前可执行措施为停车等级调整、单方向禁行和明确节点转向禁行；还支持只诊断、区域比较、需求压力与完整单项/组合设计。高峰、活动等通过小汽车需求假设检验。信号配时、施工容量与公交优先没有接入，不能把文字建议当成已执行措施。

## 怎样看出模型做了什么

右侧 **规划** 页依次保存初始问题判断、策略取舍、实验预算和每轮“观察—判断—实验—复核”。后续决策带实际观测引用，能区分模型选择、执行结果与被拒绝的方案。多组任务各自确认事实和代价，最后统一复核最初的假设；单组结束不代表整个任务结束。

顶部 **当前动作与实际进度** 显示当前动作、已完成场景及停止／继续理由。对于运行结束后才发现的解释冲突，分列“原结束依据”和“当前核验问题”；相关原解释旁标注待核对，不把后续核验当成当时停止原因。无法解析工具回复时显示“未形成可执行动作”，不能据此认为模型选了停止或已执行治理。格式诊断只保存错误类别、长度和位置，详细原生结果仍从完成场景查看。

**为什么安排这次试验** 并列模型选点时可见的所选/备选基准，显示实际速度、V/C、停车等级和小汽车量，并标清拟关闭与保留方向。下面分别列出待验证假设、什么后续结果会否定它、为何暂缓备选；备选未试不代表无效。后续停车试验必须引用最近反馈。点击观测按钮可回到对应任务、场景与方向；数值从原始字段显示，模型原文另列。缺少候选观测不发请求，无效引用不会进入治理执行。

后续停车选择新增 **这次对照改变了什么**，并列所选候选与暂缓备选相对最近试验的参数差异。位置、范围和等级同时改变时，只能比较完整方案，不能把效果单独归因于一项。这里显示的方向数来自实际动作；它不预测候选效果，也不替模型选择。风险栏另显示当轮明细的提供条数／总数，原模型文字保留以便核查。

**实测方案怎么选** 列出实际执行措施、是否满足约束及核心/邻区变化。单向组合研究还显示组合相对停车或单向单项的耗时差，单位为 pcu·h；该差值不是改善百分比。核心收益更大仍可能因邻区恶化而被拒绝。通过阈值也不表示没有代价，微小正值仍予保留。

**实测代价与模型待验证风险** 分开显示。新任务由模型选择验证需要的证据类型，数据提供情况从该轮输入生成；已有静态路段明细仍不能证明动态排队或现实成因。明细可能节选，须核对总数与完整性标记；页面有数据不一定表示旧任务的模型输入也收到过。历史模型验证说明保留原文。模型未列额外风险不表示零风险。

**原问题是否得到回答** 展示新任务在开跑前声明的判据：研究组、评价范围、需求条件、措施类型，以及“至少一个”或“所有已试措施”的量词。核心耗时降低、满足推荐约束、邻区代价合格和相对单项的额外收益分别判定。每组用自己的新基准，同一措施须覆盖全部约定需求；模型最终解释沿用原判据，不能因为措施不合格就否定实际核心收益，也不能把已出现反例的全称假设改成较弱说法。展开可看配对值并定位对应场景。

新任务还会在开跑前检查明显口径冲突，例如把“核心耗时下降”与“可推荐”混成一个判断、改变比较对象或量词。失败提议先保留，不启动仿真。仅当更正“被检验的措施类型”，或将量词字段恢复为原话明确的“至少一个/项/种”或“所有/全部”含义，就能消除冲突、原问题和判据类型保持、预算仍可完成全部实验时，模型才可修正一次；与定位和预算修正共用初始上限。换指标、改问题、猜测未明确的量词、删组、缺少预算或第二次仍错误都会停止。页面可展开原问题与当时参数，查看具体冲突、两次请求和用量。

这次修正仅让模型提交出错假设的措施选择，例如“H2 → 组合措施”或“H1 → 量词：至少一个已试措施”。原方案由程序保留，不让模型重述后改写原问题。页面明确分开实际字段选择与“原方案＋本次字段选择”；字段已应用仍不等于完整规划或交通效果通过。初始规划版本早于 v4 的档案继续显示其原有完整提议，不事后补造字段选择。

页面 **原问题与实际检验** 同时展示模型原提问，以及根据冻结范围和判据生成的明确检验问题；原话不会被覆盖。展开可见适用边界。“判定与是否通过推荐约束分开”等整句说明会在其中单独显示；说明不会被当成另一项已通过的结果，原话也不删除。真正要求“耗时下降且满足推荐条件”的双重问题仍需分别检验。旧档案按当时口径显示和核对。“交通组织及组合”可以明确排除仅停车，核心收益、推荐资格和组合增益分别检验，不能扩大被检验对象来替换原问题。

判据是模型对问题的明确解释，不自动保证与任意自然语言完全等价。无法直接观测的排队、因果或效益上限保留证据缺口；未测、重复结果不一致或控制响应未证实都不能强行通过。旧档案没有事前判据时保持原样，不在事后补写成已通过的新协议。

模型可能推翻原假设、保留基准、没有合法候选，或因预算/接口/结论错误停止。界面和报告保留这些结果，不以出现推荐或绿色状态作为智能规划通过的唯一条件。

候选对照现在分别显示计划需求、参照需求、同需求基准和候选结果状态。能安排同需求试验不代表已经取得结果；没有候选结果也不代表需求不同。已提供配对指标仍须分别核对收益和约束。这些状态来自实际输入，模型自由说明仍需独立复核。见[需求与测量状态说明](20260930候选需求与测量状态分离.md)。

## 地图对照

1. 点击一个已完成措施，选择 **对照**，查看与该措施同组、同需求的新基准；不同引擎各有自己的基准。
2. **路段状态**显示实际拥堵等级，**运行速度**显示绝对速度；若状态等级未跨档，用**耗时变化**或**速度变化**看较小变化。相同颜色不一定意味着数据相同。
3. 点击道路或列表中的方向，在两张图查看同一路段的速度、V/C、流量和变化。范围按钮可回到研究区或全网。
4. 在“收益之外，还发生了什么”点击新增过饱和道路，定位真实受影响方向。报告中的邻区总变化与单条道路变化分别解释，不能相互替代。
5. 单向措施在候选图显示机动车禁行标记，详情列出响应已核对、未通过或待核对。基准和反向保持原状；汇总速度或低V/C不表示禁行方向允许机动车通行，零流量本身也不能证明封路。

尚未完成本次基准时只显示案例道路几何，不用历史流量填充新任务。底栏注明案例与数据性质。**评估**页及**实验档案**提供完整指标、实际任务和报告入口。

## 验收与移交

每次验收保存源码版本、初始任务、实际模型请求数、每组新基准、原生执行及输入/输出、模型选项和最终解释。只有原始数据与解释一致、必需对照齐全时，才确认这一案例通过；一个案例不能证明全部自然语言表达或所有策略可靠。

新任务的输入v2记录实际发送正文的字节数与哈希；减少JSON空格不删除原始文字或不利数据。输入成本以接口报告的tokens为准，不能拿完整留档与发送副本的体积差冒充新增节省。一次探针已经降低输入用量，但“候选尚未执行”与“候选需求不同”仍被模型混淆，该例独立复核为needs_review，不能以工具结构通过替代解释质量验收。见[实际输入复核](20260930实际发送输入紧凑化.md)。

便携包内的 `scripts/validate_observed_planning.py` 提供明确限额的真实验收，需显式给出 `--live-api --native` 才会运行。输出目录必须新建，不能覆盖旧尝试。代表性混合案例上限为7次模型请求和6个新场景，内部有限修正计入同一预算。示例命令应在待验收的解压目录中执行，端口使用该包实际服务端口：

```powershell
.\python\python.exe -B scripts/validate_observed_planning.py --live-api --native --case programme --port 8769 --output 智能体实验/我的独立验收
```

完整原件核对使用包内 `scripts/verify_programme.py <总任务编号> --no-write`，不会调用模型或重新仿真。它检查本地可验证的记录与已定义的结论冲突，仍需阅读最终模型解释，不能宣称任意自然语言均被自动证明正确。

物理异机验收必须在另一台实际电脑上取得新执行记录，记录该电脑的 Windows、包清单、启动与计算结果。复制本机成果、同机换目录或隔离 Python 环境只能证明相应的传输/环境检查。未取得的部分继续标为待验证。
