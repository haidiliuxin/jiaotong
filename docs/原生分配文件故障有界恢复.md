# 原生分配文件故障的有界恢复

2026-09-23 的同预算挑战首个任务在 `M6AssignVehicle.exe` 打开 `cache/Rwm_car.dat` 时失败；第二个完整重启任务在 `cache/volume_car.dat` 处失败。两次同输入独立探针均完成七个原生模块，但根因尚未定位；首个故障材料见[诊断材料](../成果/复评/20260923_guard_native_failure/README.md)。两个失败任务均未被修补为通过任务。

为未来的同类长任务新增有界监督命令：

```powershell
python scripts/supervise_guard_challenge.py 智能体实验/supervisions/自定义唯一目录 --max-attempts 2
```

启动前要求算法、协议和监督脚本已提交，登记代码提交、源码文件摘要、案例输入摘要及最大完整任务次数。只有任务因 `M6AssignVehicle.exe` 明确报告无法打开 `Rwm_car.dat`、原生执行日志与冻结代码/输入/程序摘要均一致时，才保留原失败任务并从**新基准**开始下一次完整任务。治理政策不合格、其他文件错误、代码或数据变动、审计失败均立即停止；不会依据治理效果决定是否重跑，也不会跨任务拼接场景。

任何完成的单次任务仍须通过原始文件、选区、时序和决策重放的严格核验，再写入字节封存清单并复核清单。监督记录保存每一次尝试的任务目录与失败原因。此机制改善故障恢复的可追溯性，不消除 TranStar 原生故障，也不替代不同电脑上的真实验收。旧监督入口只识别 `Rwm_car.dat`，第二次 `volume_car.dat` 故障不符合其重启条件；它尚未完成新挑战任务实测。后续 v2 同场景恢复只覆盖两种小汽车缓存文件，也因 `Rwm_motor.dat` 中止；对应规则分别见[原生恢复修订](20260923全网安全门槛同预算挑战原生恢复修订.md)和[车型缓存恢复 v3](20260923同预算挑战车型缓存恢复v3.md)。三个版本的状态和结果必须分别披露。
