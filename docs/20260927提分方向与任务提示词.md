# 后续提分方向与新对话任务提示词

**优先级已按用户最新要求更新：下一阶段必须开发带API设置入口的大模型交通Agent，完整运行与异机测试后置，跨城市暂不推进。请先执行[大模型Agent开发方案](20260927大模型交通Agent开发方案.md)。下列A—E保留为支撑工作与后续备选，不再把大模型列为可不做项。**

持续模式按用户澄清采用“自然语言加入环境变量 → 沙盘变化 → 全区域持续观测 → Agent自主调整”，见[补充设计](20260927持续监测与主动调整设计.md)。环境、监测与治理独立运行，无新消息也须工作；现有静态批次能力不足以宣称这一目标完成。

依据[项目事实基线](../项目事实基线与新对话入口.md)和本地赛题原文，以下是下一阶段建议，不是已经实现的功能，也不承诺具体加分。涉及评分项相互重叠，不能把表中分值相加成预计收益。一次新对话只推进一个可验收目标，避免再次把代码、研究、打包和展示混为一轮无限优化。

## 2 各方向的具体任务与完成标准

### A 统一最终报告与证据入口

将散落的正式报告、增补和最新Markdown整理成一版有明确截止版本的主报告、手册和评分导航。主报告聚焦一个主问题和一条主线：停车干扰 → 候选措施 → 真实分配 → 外溢约束 → 反馈回退 → 跨需求建议。单向与禁转用扩展边界或负例说明，避免抢占主线。

每个关键结论绑定“代码版本、任务号、数据来源、对比口径、原始核验入口”。加入同预算v3的不全面胜出、教学无候选、停车1级的条件和已有局部代价。确定一个评审首先打开的入口，五类材料各有明确位置；运行包和阅读包分清用途。

特别补齐教学无候选任务的移交范围：当前原始基准与登记在本地未跟踪目录，GitHub只有协议说明及审计摘要。若将其作为可独立复查的提交证据，应按“基准完成、无候选”的真实状态制作可移交档案和专用核验，不能套用完整成功任务封存结果；暂未制作时明确标出本地与已发布材料的区别。

完成标准：新版报告和手册可独立阅读；图表数字可追溯；评分条款都有证据或缺口标注；所有引用文件可打开；旧发布原样保留；导出与录像回看标明新增模型调用为0。若生成新PDF或DOCX，逐页检查版面。已有录像是否足以满足“实机演示”由正式提交要求判断，不擅自宣称主办方认可。

### B 提高诊断可迁移性

第一步只研究已保存的新基准：为什么10条路经过其他筛选却都被软件 `VC>1` 排除？核对软件V/C分母、管理修正容量、速度形成机制及停车字段，区分“规则过窄”“当前确实无符合定义的拥堵”“历史附带结果与当前配置不同”等解释。目前只能确认新旧输出不同，原因尚不能凭差值推定。

若有足够交通机制依据，再设计一个版本化的通用诊断方案。例如分别定义过饱和瓶颈与低速停车干扰的适用条件，给出不适用和无候选的解释；不要为了让案例4有结果而把1改成0.8。无论采用何种新规则，都用南京与教学数据检验适用条件、异常排除和来源标注。

首次新调用前固定任务、输入及代码摘要、选点规则、预算、需求点、评价范围和成功／失败判据；新任务号保留v1 `no_candidate`。先只运行一个有界的新协议。若取得候选，再完成每个需求的配对基准、治理、反馈与复跑；没有候选或无收益照实结束。

完成标准：诊断规则有可检验依据；新真实任务与审计对应；负结果同样可复查；只有完成治理、反馈、跨需求及复跑才描述为相应闭环。新规则已受案例4负结果启发，开发试验不能写成完全盲测。外部保留验证需要另行选取未参与规则开发的数据或区域。

### C 同预算下提高搜索效率

将“多算几个方案”改成一个明确问题：在相同允许动作和安全约束下，能否用更少原生调用找到合格措施，或在固定预算内获得更好的收益与代价权衡？可先研究根据失败原因选下一条路、减少重复评估、按真实观测决定强度或停止。不要预设新优化器必然优于固定网格。

对照必须含现有强固定网格和反馈回退；候选空间、逻辑预算、共享场景计费、需求配对和硬约束对齐。事前设定主要指标，例如首次得到跨需求合格措施的调用数、最终推荐的全网与邻区指标、最差需求核心变化；并披露强度、失败、未用预算、重试及实际耗时。不得只挑核心收益最大的图。

开发可使用历史任务，评估任务必须重新登记。冻结新的历史排除清单，旧 `config/guard_challenge_history.json` 保留；纳入此前失败与已见输出区域，防止把开发区域重新称为未见区域。不能把同输入复跑作为独立随机样本计算显著性。

完成标准：一个版本化改进、一个公平预登记对照、全部终态与匹配审计。若最终同推荐且更多调用，结论就是没有效率增益；停止这一有界阶段，不以临时换规则或换区域追求赢的结果。

### D 补强交通机制与实施条件

把现实设想、实际修改字段、原生中间量、最终交通指标串起来：`ManageL`停车类别 → 管理修正容量／阻抗 → 分配流量与速度 → 核心及外溢。软件V/C与管理修正负荷分别解释。优先使用现有配对结果复核；确需新增场景时先固定单变量试验，明确这是模型内部机制验证，不是现实因果识别。

区分停车2级的“需求较大且规范”和1级的“需求少且规范”。列出停车需求承接、装卸位置、步行距离、执法、居民通达与公交条件。缺数据时将其列为实施前提和调查表，不能捏造泊位数、费用、人群收益或将措施数折算成真实成本。

完成标准：一张可追溯参数和机制表、一组真实中间量与输出对照、一份明确的措施适用条件及未验证事项；必要的参数／邻区敏感性必须区分历史复评与新仿真。若这些证据不足以支持加强治理，应降低推荐的确定性，而不是隐去条件。

### E 对齐可运行版本并做独立验收

在选定的最终源码提交上构建新版本便携包，不覆盖v4/v5。把其代码清单、任务卡、默认页面、报告与演示对齐。先在同机独立目录确认环境、LFS实体、中文及空格路径、真实四场景停车流程、基准复跑和封存；若发布时宣传显式禁转／单向能力，分别执行对应真实验收，不能借用停车结果。

再准备另一台Windows电脑可直接运行的验收步骤和记录收集工具。第二台机器必须实际生成新任务，保存机器环境、程序版本、输入摘要、调用日志和输出，由同一口径核验。若当前没有第二台电脑可访问，先完成可移交包和操作步骤，把异机一项明确列为待执行；没有必要因此停止能完成的本地工作。

完成标准：新包可复现构建、版本及内容可核对、本机真实验收通过；若声称异机通过，必须有该机器的新模型执行证据。程序原生错误、授权、依赖或进程中断照实记录，不能用复制档案验证替代实际求解。

## 3 暂不优先投入什么

继续堆测试数量、重复相同确定性求解、只增加地图特效，通常不会直接填补当前主要证据缺口。大模型现已被用户列为项目必做项，重点是任务理解、实际工具选择及仿真反馈后的再决策；执行继续经过已有校验与工具边界。聊天流畅本身不能替代仿真反馈证据。

## 4 可直接复制的新对话提示词

在同一 `F:\ITS比赛` 项目中新开对话，把下列“通用开场”与一个方向的任务段一起发送即可。不需要粘贴旧聊天、所有日志或全部报告，也不用恢复已经结束的9月23日心跳。

通用开场：

```text

先核对当前Git分支、HEAD、工作区修改、相关进程和原生运行锁。cf464c4f是9月27日核对的功能代码基线，不要求退回该提交。
每项结论绑定数据来源、任务号、代码版本、指标口径和证据路径。核验记录只说明其当时结果；不把读取记录称为新独立复算。不可将旧输出当新基准、同机复制当异机、回看当连续实时求解、测试数量当官方分数。
保留原始数据库、封存任务、旧协议及失败证据。新实验先登记规则和预算，使用新目录；运行期间不改其代码快照依赖，按实际进程监测，不重复启动。严格区分原生新运行、历史复评、资料导出。
选定本阶段完成标准后继续执行授权范围内的工作；仅在缺少不可替代的信息或外部资源时询问。阶段结束给出实际结果、未完成项、验证方式、改动文件，并更新本交接入口。不要同时开展其他方向。
```
