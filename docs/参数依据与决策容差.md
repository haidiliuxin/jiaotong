# 参数依据与决策容差

版本：2026-09-19，推荐规则 `tolerance-v2`。依据为本仓库软件手册、可检查的代码和保存的模型结果；交接清单是改进建议，不是赛事新增评分标准。

本地来源：[说明书文本](../工作材料/文本摘录/城市交通版说明书.txt)表2-12（文本约996—1015行）和基础文件1-40（约8334—8344行）。手册停车类别完整对应为0无影响、1轻微、2中度、3较严重、4严重、5阻塞。**类别不是线性容量系数**：从3改成1不代表容量增加三倍；容量和流量由真实管理预处理、分配和输出给出。

## 选点和约束的性质

停车自动候选来自 `traffic_agent/data.py::diagnose`：有效城市2/3类道路、停车3/4、长度0.1—1.5km、流量至少500pcu/h、1<V/C≤4、速度<40km/h、有明确非匝道名称；按qL/v排序，首个候选附近按指定跳数选点。

这些条件用于聚焦有一定交通量、存在停车干扰且能形成局部治理实验的路段；**不是手册规定的必选阈值，也不是从实际治理效果标定出来的最优参数**。高V/C极端值、短连接线及低流量段被过滤可能产生选择偏差。显式禁转使用独立的指定转向验收条件，不冒称通过了停车自动选点。

| 参数 | 默认值 | 实验解释 | 本次检查方式 |
| --- | --- | --- | --- |
| 邻区 | 固定核心之外2跳 | 限定邻近外溢核查范围 | 固定原核心/原措施，重算1/2/3跳；不重新选点 |
| 邻区qL/v增幅上限 | 0.5% | 允许小幅外溢的研究假设 | 逐项改为0、0.25、1% |
| 全网qL/v增幅上限 | 0.1% | 避免以明显全网恶化换局部改善 | 逐项改为0、0.05、0.2%；禁转/单向分支原有全网严格改善要求仍保留 |
| 邻区新增过饱和有向里程 | 0.1km | 限制新出现V/C>1的路段毛长度 | 逐项改为0、0.05、0.2km，不以别处缓解抵消 |
| 目标核心速度 | 25km/h | 触发进一步强度试验的停止条件 | 非政策硬合格标准，未标定为最佳目标 |

阈值扫描见[冻结网格](../examples/review_protocol_20260919.json)和[复评报告](../成果/复评/20260919_v2/report.md)。这是已知历史结果的探索性再分析；不是独立盲测，不会修改原档案的合格判断。

## 近似相同时怎样选择

旧规则可能因为极小的全网耗时差异选择组合措施。新版先保留全部原约束通过、证据完整的候选，然后按以下顺序筛选：

1. 取当前候选中最好的全网耗时变化率，仅保留比它差不超过 **0.001个百分点** 的项。
2. 在剩余项中取最好的邻区变化率，仅保留差不超过 **0.01个百分点** 的项。
3. 在剩余项中取最小邻区新增过饱和，仅保留差不超过 **0.001km** 的项。
4. 再按不同措施数量较少、停车1级措施较少、名称稳定排序。

跨需求时使用同一措施的最差变化率；每个需求使用自己的无治理基准。任何需求失败或缺测，都不能因容差而取得统一推荐资格。单需求结果不声称跨需求稳健。

上述容差是**公开的决策分辨率假设**，用于表达何时愿意为简化实施而放弃极小的计算优势。它们不是根据TranStar输出误差推导的统计阈值：同输入重复数组完全一致只能支持确定性复现，不能证明模型无误差、效果显著或现实有效。当前尚缺参数标定和现实实施成本，不把它们称为经校准的“最小有意义效果”。复评同时给出默认容差的0、0.1、1、10倍结果，供评审观察规则依赖。

复杂度采用二元顺序 `(不同措施数, 停车1级措施数)`：一个停车方向、一项禁转或一项闭边各计一项；停车1级单独作为更强假设的次序，不将等级差解释为线性成本。名称仅用于完全同序时稳定复现。

每一筛选步都以当前集合的**固定最优值**为锚，避免“A近似B、B近似C”把相差很大的A和C串成一组。精确Pareto前沿继续披露；容差规则可以选择有微小数值劣势但更简单的措施，界面会显示原因和指标差。

## 版本与证据保护

旧任务未写 `recommendation_version` 时仍使用 `legacy-v1`，旧协议与验证结果保持原语义；新版任务卡明确写 `tolerance-v2`，在首个模型调用前保存到 `plan.json`。网页新任务采用v2，命令行旧JSON仍使用旧规则。

历史档案的新规则复评输出到独立目录，明确区分原冻结推荐、旧跨需求筛选和v2跨需求筛选。未测的需求、候选和现实成本不会被补造。所有qL/v指标只表示路段行驶时间消耗，不含独立核算的全部节点延误，不能叫作全系统总旅行时间。

## 绝对耗时容差兼容

保留协作者9月14日新增的`recommendation_tolerance_pcu_h`（0至100，默认0）。它仅用于standard模式：以最低全网qL/v为参照，在预设绝对pcu·h范围内优先少参数改动和较温和停车类别。其旧API和4项原测试继续有效；没有因v2引入而删除。

非零绝对容差不能与`tolerance-v2`或主动跨需求搜索混用，任务校验会明确报错，避免将pcu·h和百分点混为同一门槛。旧JSON缺省字段不新增到历史协议；若历史任务明确保存了0，序列化也保留该字段。网页新任务使用v2，需绝对容差时以JSON明确选择standard旧版规则。
