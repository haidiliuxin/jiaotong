# 单向仿真编译器修复（2026-10-04）

## 用户任务与故障

`20261004_171646_aea416` 的大模型规划生成了三组研究。第一组“停车＋单向组织”在建立专用原生运行环境时，以 `FileNotFoundError: [WinError 2]` 失败；后两组未执行，原生场景计数为 0。该失败保留在原任务记录中。

故障点是 `hard_access.install_runtime()` 调用 `gcc` 编译原生包装器时，本机服务进程的 `PATH` 没有 MinGW GCC。此前启动服务只使用默认停车任务做环境检查；停车无需编译器，无法替后续由模型选择的单向/禁转研究检查编译器。

## 修复

- 在本机项目外安装 WinLibs 的 Windows x86_64 MinGW GCC 16.2.0（UCRT），存放于 `F:/jiaotong/test-tools/winlibs-16.2.0/mingw64/`。下载自 WinLibs 官方链接的 GitHub 发布包，ZIP SHA-256 为 `c1f52294597c0b73786b2a78eb5d176d89226d2f21875eab75e783a8b1cefcc4`。未把编译器或编译产物提交到仓库，也未修改系统 PATH。
- 使用启动参数 `--compiler-bin F:/jiaotong/test-tools/winlibs-16.2.0/mingw64/bin`，只将工具目录加到服务及其子进程的 PATH。
- 调度器在接受已规划任务的执行动作时，检查每组单向或显式禁转研究的本地依赖。检查失败时立即返回明确错误，不创建仿真任务或声称已执行；检查通过后仍按原任务与原生程序执行。
