# 离线自动回归说明

`.github/workflows/offline-regression.yml` 会在每次 push、pull request 和手动 `workflow_dispatch` 时运行完整离线回归。环境为 GitHub 托管 Windows、Python 3.12、Node 24；不安装 pip/npm 依赖。工作流只申请 `contents: read`，不保留检出凭据，不需要配置模型密钥或其他 secrets。

统一入口是 `scripts/run_offline_tests.py`。本地准备好 Python 3.12 和 PATH 中的 Node 24 后，在仓库根目录执行：

```powershell
python scripts/run_offline_tests.py
```

入口会按顺序运行整个 `tests/test_*.py` 的 unittest discovery，以及以下四个 Node 测试：

- `tests/test_map_view.cjs`
- `tests/test_dispatch_ui.cjs`
- `tests/test_planner_view.cjs`
- `tests/test_choice_view.cjs`

Python discovery 的参数等价于 `python -m unittest discover -s tests -v`。入口显式优先加载当前仓库，避免嵌入式 Python 的 `._pth` 意外指向另一份应用。每项任务保留标准输出和错误输出；任一任务返回非零、无法启动或缺少测试文件时，总入口返回非零。已启动的任务失败后，仍运行其余任务，便于一次查看全部结果。CI 的测试步骤直接使用这一退出码；日志在 Actions 页面对应运行的步骤中查看。

离线测试使用合成交通数据、临时目录、模拟模型回复和封存 JSON；HTTP 测试仅访问本机回环服务器。它们检查控制器、协议、报告、界面逻辑和失败边界，不调用外部模型 API，不运行 TranStar 原生程序。CI 下载源码和配置 Python/Node 时仍需联网；这里的“离线”指测试阶段无需外部服务或实际模型计算。

工作流关闭 LFS 下载并设置 `GIT_LFS_SKIP_SMUDGE=1`。非 cone 模式的稀疏检出包含 `.gitattributes`、`.github`、`traffic_agent`、`tests`、`scripts`、`config`、`examples`、`start.ps1`，以及明确被语义契约测试读取的 `docs/validation/20260928_quantifier_live_manual_review.json`。`tests/fixtures/sealed_planning` 中的 JSON 保留原始字节，并由加载器核验 SHA-256。历史 ZIP、南京案例源数据、原生运行环境及大量历史实测输出均不属于当前离线测试依赖。以后若新增测试直接读取仓库其他文件，应同时更新稀疏检出范围，并在独立检出中验证完整回归。

工作流参考当前官方 [actions/checkout](https://github.com/actions/checkout)、[actions/setup-python](https://github.com/actions/setup-python) 和 [actions/setup-node](https://github.com/actions/setup-node) 文档，采用 v7。Python/Node 固定主次版本范围，补丁版本由托管环境解析，因此可能与上述本地版本不同。工作流尚未在 GitHub 上执行；首次推送后应检查实际 Actions 结果。通过离线 CI 不代表真实模型连接、授权模型程序、完整仿真或原生扩展验收已经通过，这些仍需各自独立的实际运行证据。
