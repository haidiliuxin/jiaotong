## 1. 准备与clone

使用Windows和Python **3.12**。应用主线使用Python标准库，不需要安装`requirements-viz.txt`中的文档绘图依赖。安装Git及Git LFS；若要测单向、禁转及其组合，还需要Windows MinGW GCC，目标应为`x86_64-w64-mingw32`。先测停车主线可不装编译器。

仓库包含历史文档、图片、视频及软件。以下在clone时暂缓LFS下载，再仅获取应用所需程序与南京基础路网，避免为启动下载全部历史成果：

```powershell
git lfs install
$testPreviousLfsSmudge = $env:GIT_LFS_SKIP_SMUDGE
$env:GIT_LFS_SKIP_SMUDGE = '1'
try {
    git clone --depth 1 https://github.com/Tabris-Ayanami/its-transtar-agent.git
} finally {
    if ($null -eq $testPreviousLfsSmudge) {
        Remove-Item Env:\GIT_LFS_SKIP_SMUDGE -ErrorAction SilentlyContinue
    } else {
        $env:GIT_LFS_SKIP_SMUDGE = $testPreviousLfsSmudge
    }
}
Set-Location -LiteralPath .\its-transtar-agent
git lfs pull --include="方案1流程验证/runtime/**,南京市案例数据库/南京案例/基础路网/**" --exclude=""
git rev-parse HEAD
```

每步成功后再继续。目录可以位于其他盘，不需要`F:\ITS比赛`。其余LFS成果仍可能显示为指针；应用启动所需范围已在上述命令内。要阅读历史二进制附件，可另按所需目录拉取。上述两目录的204份LFS文件约709MB；本机导出已按固定提交中的LFS对象哈希核对，未证明远端LFS下载成功，另一台机器需保留实际下载结果。见[本机独立目录核验索引](validation/20260930_clone_source_handoff_review.json)。

## 2. 检查与启动

源码离线回归不请求模型、不运行原生场景，也不再需要下载历史证据 ZIP。可以在仓库目录运行：

统一入口为 `py -3.12 scripts/run_offline_tests.py`，会执行完整Python及4组Node测试，并在任一组失败时返回非零。分支提交也会触发[GitHub离线自动回归](离线自动回归说明.md)。配置损坏恢复、原生清理及空间预检见[可靠性优化与恢复说明](20261002可靠性优化与恢复说明.md)。

```powershell
py -3.12 -m unittest discover -s tests -q
# Python检查成功后再继续；Node需在PATH中
node tests/test_choice_view.cjs
node tests/test_dispatch_ui.cjs
node tests/test_map_view.cjs
node tests/test_planner_view.cjs
```

原问题及失败回归所用的7份JSON原始字节、源ZIP及成员哈希记录在`tests/fixtures/sealed_planning/manifest.json`，普通回归无需另拉约379MB的ZIP。缺少这些已提交JSON时应修正源码下载，而不是跳过测试。首次安装Python后若`py -3.12`失败，可用`py -0p`检查注册路径，再用真实Python 3.12可执行文件代替以下`py -3.12`；依赖检查会记录实际路径及版本。

在仓库目录的PowerShell运行：

```powershell
# 只检查环境，不请求模型、不运行原生场景
py -3.12 -m traffic_agent.startup --mode check

# 启动工作台；服务在该终端持续运行
py -3.12 -m traffic_agent.startup --mode serve --port 8769
```

浏览器打开`http://127.0.0.1:8769`。也可用`./start.ps1`启动；若执行策略限制脚本，使用上面的Python命令。端口占用时改成8771等空闲端口，不结束未知服务。任务执行中保留终端；待任务结束后可按Ctrl+C关闭自己的网页服务。

若测单向或指定禁转，先核查实际编译器路径，并用同一路径启动：

```powershell
py -3.12 -m traffic_agent.startup --mode check --task examples/oneway_changjiang.json --compiler-bin C:\mingw64\bin
py -3.12 -m traffic_agent.startup --mode serve --port 8769 --compiler-bin C:\mingw64\bin
```

`C:\mingw64\bin`只是示例，改为该机器实际路径。依赖检查会识别缺失程序、LFS指针、错误编译器目标等；通过不代表软件授权和实际原生响应已通过。失败时保留原记录，修正依赖后另留新检查记录。

## 3. 本机设置模型

点击右上角“API 设置”，填写：

| 项目 | 内容 |
| --- | --- |
| API基址 | `https://tokenrhythm.studio/v1` |
| 接口类型 | Chat Completions |
| 模型 | `deepseek-v4-flash` |
| 密钥 | 在该机器设置页输入并保存 |

保存设置不产生模型请求。可只做一次“测试已保存配置”；该测试会请求服务。密钥由该Windows用户加密保存；从原电脑复制加密配置不能替代在新机器设置。回传应用任务证据及检查记录即可，本机模型配置不属于测试证据。

密钥必须由所填服务签发，模型名称也必须被该服务允许。DeepSeek官方密钥不能据名称相同而假定可用于TokenRhythm转发服务。设置窗口展示当前已保存的地址、模型和协议；手动测试针对已保存配置，未保存的输入不会生效。HTTP 401表示授权未通过，应核对平台、基址和模型权限；403还可能涉及客户端接入限制。仅凭状态码不能认定密钥无效。服务失败时停止，不自动重试、换地址、换模型或改协议；服务未报告tokens时显示未知。

确认左侧模式为“大模型自主规划”。只填自然语言；无需选择停车模板、手填路段或提前指定治理等级。点击“自动编排并运行”一次（规则模式的按钮为“匹配并开始”）；查看记录和刷新页面不应发起新的模型研究。

页面顶部的本次规划状态与当前查看的实验分别显示。规划失败时旧实验地图可继续查看，其收益不属于新请求。刷新会展示最近一次初始模型规划失败记录并恢复原问题，不会自动重发；查看其他档案也不请求模型。地图另行显示核心速度与追加治理目标、全网过饱和净增/可用毛新增；追加治理目标与推荐硬约束分别判断，不能把净变化当毛新增。

建议先测下面这条，最多3个原生场景，无编译器要求：

> 请研究环洲路的停车干扰拥堵，比较两个不同区域的停车治理方案。先根据本次新基准选择区域与停车等级，再依据第一个方案的实测结果，选择另一区域做同等级对照。需求系数1，最多治理1条方向，总计3次仿真，不复跑。分别检查核心耗时是否下降、各区域是否恶化以及邻区是否满足原定门槛；保留失败结果，完成比较后推荐约束内的方案或保留基准。

应观察到：初始计划冻结3次上限；先运行新基准，再由模型选择首个位置和等级；收到实测后选择另一区域同等级对照；最后读取结果并复核。完整执行为3场景／21个顶层模块，正常至少4次模型请求；初始及决策的有界修正均计入本任务最多7次请求。失败、超限或缺测均应明确显示，不能为凑齐次数自动宣称完成。一次完整任务足以形成首轮异机证据，不必反复运行同一问题。

## 5. 按事实记录通过、失败、未做

重点核对以下项目：

| 项目 | 核对内容 |
| --- | --- |
| 模式与输入 | 左侧模式、右侧当前任务一致；原问题保留，未通过改写问题完成检查 |
| 模型闭环 | 首次选择来自新基准；后续决定引用实际反馈；列明哪些方案已执行、哪些仍是备选 |
| 预算与停止 | “总计3次”仍为3；请求次数和原生场景数分开；未完成比较时不显示完整结论 |
| 参数与地图 | 治理位置、停车等级、控制方向来自实际执行；点击场景可定位；同需求前后图范围与图例一致 |
| 效益与资格 | 原生控制响应、核心改善、邻区两项门槛、推荐资格分别判断；净增与毛新增不混用 |
| 语义 | 未测方案不当成已知收益；两次失败不推为“普遍无效”；独立区域收益不相加为联合效果 |
| 原生证据 | 每个完成场景有新模块日志和结果；任务及失败记录保留，报告可阅读 |

软件自动核验只能核对已实现的字段和文件，仍需要人看自由解释。当前已知：最新环洲路完整尝试完成2场景后工具JSON失败；新源码提供一次受预算约束的格式修正，离线边界通过，独立真实回复已合法，但生产自动恢复完整过程待验。该回复还存在从两次超限推出普遍溢出的过度推论；结构通过不代表语义已通过。

若该任务正常完成，可运行只读完整核验（使用页面给出的**总任务ID**）：

```powershell
py -3.12 scripts/verify_programme.py <总任务ID> --no-write
```

把占位符替换成实际ID，命令中不保留尖括号。状态为incomplete／failed时完整验收器应拒绝出具通过结论；保留失败原件，反馈具体停止原因。

停车测试之后，如需单向与组合验收，可新增一条独立自然语言问题要求“比较停车、单向及组合”，先核对预览中的实际场景数、控制方向与编译器依赖。此类完整单项／组合至少4个场景；停车通过不能代替控制适配器通过。最终以实际记录核对关闭与保留方向。
