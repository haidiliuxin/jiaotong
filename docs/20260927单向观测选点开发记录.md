## 已实现

此前单向组在新基准中按规则选择第一个合法方向，再固定执行四项对照；模型只参与初始分组、组间排序和最后复核。本阶段新增 `oneway-target-v1`：

1. 先运行本次 Vehicle1 基准，读取实际速度、V/C、总流量与小汽车流量。在用户指定道路／方向内按既有瓶颈规则搜索至多200项，保留至多4个通过公交保护、三类车型边界绕行及反向停车条件的方向。
2. 模型读取本次全网基准与各候选双向路段的观测、公交检查数量和绕行代价，选择一个候选。目录不含历史最优策略或尚未执行的治理收益；指定方向不会放宽。
3. 将模型所选方向写入双向停车、单向禁行及组合的实际措施，固定其核心、邻区和全网范围；每个约定需求都执行同位置的基准、停车、单向和组合。未选位置只表示未试验，不能宣称已证明无效。
4. 原有末轮请求完成实测、假设和总任务复核。单向组预留一次选点和一次复核请求；单组最少3次模型请求包含初始自然语言规划，原生预算仍为每需求4场景加约定复跑。总模型上限保持6次，超出时不悄悄省略后续组。

选点超时、非法工具回复、目录外方向或预算不足均停止新增治理，保留本次基准和失败。不会回退为规则首项，也没有自动付费重试。规则入口保留原先的首个合格方向协议。

新增冻结候选目录、选择前后时间、摘要、模型输入与实际方向的一致性检查。原件核验器从本次原生基准和拓扑重建目录，检查实际治理采用事前模型所选方向，并继续核对每项输入、输出、控制响应和完整四项对照。停车和单向的规划标识分开，避免把单向误判为停车强度搜索。

界面显示拟关闭／保留方向的基准速度、V/C、停车条件、小汽车量、绕行代价、模型选定状态与基准地图入口。页面明确说明图检查通过不等于治理有效。新代码预览仍为 `http://127.0.0.1:8772/`，检查没有活动调度且原生锁可取得后，正常停止并更新了本对话管理的预览终端；8769、8770、8771历史服务未改动。
