# 全网毛新增风险约束验证计划

本轮在原有邻区毛新增、邻区耗时、全网耗时和核心改善条件之外，增加可选的全网毛新增过饱和有向里程上限。它统计同一需求、固定全网范围中，基准 V/C≤1、候选 V/C>1 的路段长度；任何其他路段从过饱和恢复都不能抵消这一数值。旧任务不提供新字段时，比较结果结构和原推荐保持原样。

## 已知结果的回顾性诊断

对已封存的 v4 显式禁转任务 `20260923_025908_fbc62a` 使用 0.1 km 上限作只读试算。这一数值是在原任务完成后选的，**不是**事前注册实验。来源任务、原始指标、禁转响应和建议均不改写，也不新增 TranStar 调用。试算核对原比较字段与封存原始数组一致，再追加新门槛。结果仅用于检查安全规则的作用，不解释为新算法提升交通效益。

## 新任务真实流程验收

在调用模型之前冻结 [`examples/parking_network_guard_quickstart.json`](../examples/parking_network_guard_quickstart.json)。采用案例原始停车任务，需求只测 1.0，预算 4 场景，复跑基准，并把全网毛新增上限固定为 0.1 km。不依据此次结果改动任务卡、区域或阈值。无论最终推荐停车候选还是基准，保留所有失败记录。

验收条件：来源预检通过；实际启动原生 TranStar 模块并生成 4 个新场景；独立核验原始输入输出、决策和复跑数组；每个候选的新增全网里程可从两份原始 V/C 数组重算；门槛超过时必须拒绝，未超过时仍须满足其他约束。该单需求新任务只证明规则正确贯穿真实求解，不支持跨需求稳健、跨城市迁移或官方分数提高的断言。

后续需要在新区域、事前冻结门槛和等预算基线下比较风险与核心改善，才能评价这条约束对比赛效果评分的净影响。

## 执行结果（2026-09-23）

任务卡与实现先在提交 `3a85a579` 固定，随后启动新任务 `20260923_043018_f34e33`。实际完成4场景、28次原生顶层调用；`verification.json`严格核验通过，封存清单包含2346个文件，`portable_verification.json`再次核对清单字节、输入输出和四类32981行基准复跑数组，均通过。
