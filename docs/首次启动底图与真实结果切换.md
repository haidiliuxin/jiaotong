# 首次启动底图与真实结果切换

新的运行包没有历史任务。原界面会长期停在“读取中”，地图为空；现在先展示案例自身的道路几何，右侧明确提示先预览任务、再启动仿真。

## 数据边界

`traffic_agent/reference_map.py`只读取案例道路、节点坐标及匹配的SHP，不读取任何`result`文件，不调用模型。返回数据没有速度、流量、V/C、治理前后值、评价指标或需求系数。本案例实际显示32060条有向道路，均按有向端点及坐标匹配SHP。

缺少SHP或端点不匹配时采用节点直连并明确说明；只有全部道路匹配且PRJ声明相应投影时才显示米制比例尺。缺少坐标、重复节点或非有限坐标会报错，不用虚构坐标补图。

## 界面行为

- 尚无任务或首个基准未完成：统一颜色显示几何，保留缩放、拖动、道路搜索及端点、长度查询。关闭速度着色、基准/方案对照及研究区定位，隐藏尚无含义的差异指标卡。
- 首个真实基准完成：切换到该任务实际输出，恢复速度、流量、V/C和场景选择。
- 方案完成：继续使用原有同需求基准配对和固定评价范围；几何底图不参与推荐或合格性判断。
- 切换任务时：取消旧地图请求，不能让较慢的底图响应覆盖已完成场景结果。

接口为`GET /api/reference-map`，只使用服务启动时配置的案例，不接受请求参数指定文件或目录。`scripts/preview_reference_map.py`是只用于界面检查的只读服务，拒绝模型启动；正常操作仍使用统一启动器。

## 验收

自动检查覆盖无`result`目录时正常显示、响应中不存在仿真值、SHP方向/坐标匹配、无效坐标失败，以及HTTP接口不会执行Agent或创建任务。浏览器检查应同时覆盖空任务底图、真实道路搜索、首次基准完成后切换、方案图与双图对照，不能仅凭接口返回成功声称地图完整可用。

本次底图检查在没有任务的目录及正在接续的便携真实任务目录进行，不修改已封存运行包或历史实验。旧运行包的完整性记录仍对应其原版本；只有重新构建并验收后，新交付包才包含此界面改动。
