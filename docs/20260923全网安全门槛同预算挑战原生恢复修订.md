# 全网安全门槛同预算挑战：原生恢复修订

2026-09-23，原协议 v1 的两次真实任务分别在 `case_002` 打开 `cache/Rwm_car.dat`、`case_006` 打开 `cache/volume_car.dat` 时中止。两个同输入场景随后都在独立目录完成全部七个 TranStar 原生模块；这说明失败不是这两组输入的确定性不可解，但**故障根因仍未知**。两次中止任务继续标记为失败，不能拼接、补写或发表为通过。已观察到部分治理输出，因此本修订不再称完全未见输出的盲测。

此 v2 修订保留 v1 的区域排除登记、从新无治理基准选区、三档密度、两策略控制器、候选优先级、需求 0.9/1.0/1.1、每区每臂 16 个逻辑场景、至多四候选，以及邻区与全网耗时和毛新增过饱和硬约束。唯一执行变化是：`M6AssignVehicle.exe` 明确报告当前场景自身 `Rwm_car.dat` 或 `volume_car.dat` 打开错误、退出码为 1、前三个模块成功、场景输入没有被改写时，同一场景最多额外尝试两次，整任务最多额外尝试 20 次。任何其他错误或超限立即终止任务，不根据治理效果选择是否重试。

失败场景和日志原字节移至同任务 `native_attempts/<场景>/attempt_<序号>`，随后从原南京案例重新生成**同名、同措施、同需求**的场景。失败尝试没有完整结果，不能提供策略观察；成功结果的执行前输入摘要须与每次失败尝试一致。成功物理场景与两臂逻辑场景计费规则不变；报告额外列出失败尝试数量和失败原生模块调用数。独立审计检查输入、错误文件、模块序列、时间顺序、追加日志、策略决策重放、原始数组和代码快照，再允许封存及导出。
