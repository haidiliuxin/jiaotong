[Token Rhythm 接入文档](https://tokenrhythm.studio/docs/api-integration)明确要求 DeepSeek 的 `tool_choice` 使用字符串。适配仅匹配指定服务的 HTTPS `/v1` 与 DeepSeek 模型：将指定函数转为 `required`，并把工具列表收窄到该函数；其余服务和 Responses 协议不变。不会增加工具权限。第二次实际返回仍错误追问，因此**格式兼容修正不能视为规划质量已经修复**。

这些模型公开提议均承认自动选区能力，却仍要求用户先提供道路。最新修正也没有改变这一错误前提；不能据此降低目标，也不能由程序偷偷生成一份固定停车方案冒充模型决策。

## 已实现

- `initial-plan-review-v1`：只有本地可判定为错误的执行前提，才能触发一次工具反馈修正。反馈包含原错误、执行范围、已用请求数；保留原始用户请求及第一次工具调用，仍由模型重新选择执行、澄清或能力缺口分支。
- 一次初始规划＋至多一次修正均计入原有6次总模型预算。修正后重新核算必需实验与最终复核成本；预算不够则保持待补充，不减少必需区域、强度比较或复核，也不启动仿真。
- 接口错误、截断、结构错误、占位内容、缺少工具回合上下文、第二次仍无效均停止。真实定位歧义和未接入能力不触发修正。刷新与读取历史不发起模型请求。
- 第一次失败独立保留；第二次有会话号、次序与关联编号。原工具回合只保存在进程内存中；持久化仅保存公开提议摘要、程序校验反馈、受限用量字段，不保存原始模型回复、隐藏推理或密钥。
- 执行前冻结初始请求记录摘要；总任务核验检查先后次序、原请求、失败关联、用量及总请求数。历史单次初始规划保留原核验口径。
- 工作台说明一次修正上限，展示初始失败和修正状态；摘要合计两次用量，未知用量单列。规划通过只显示等待执行，不显示研究完成。
- 本地付费验证器的预览等待上限容纳两次顺序调用；连接仍各自受设置的超时限制。新旧服务协议不一致时在付费请求之前停止。便携必要组件清单加入新模块，旧包没有被改写。

`480e6e0c` 的后续改动是 `traffic-plan-decision-v3` / `planning-scope-v2` / `planning-prerequisites-v1`：发送前依据原文、已匹配道路和显式拓扑确定可追问的定位类型。自动选区且没有未解析定位标记时，实际工具结构不再开放 `needs_input`；真正未知的道路、相对方位和缺少禁转目标仍开放对应追问。模型仍可编排原有研究、策略、假设与取舍，或指出必需能力缺口，程序没有生成替代方案。

定位权限与首次尝试一起记录、事前冻结并核验；后端仍独立校验回复，忽略工具结构的错误追问不会被当成执行计划。已知道路不能通过只引用名称后半段重新变成未知道路，周边影响等评估条件也不当成地点。这里使用案例路名和既有受支持的地点／方位语句检查，**不是通用地理编码**，不能声称任意地名或任意自然语言都已理解。
