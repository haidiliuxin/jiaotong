# RC7 回指定位误追问

## 真实失败

RC7 基于提交 `4b53b74d` 构建，16,162 文件清单及同机异目录环境检查通过。使用自然语言“请研究长江村路停车拥堵。先在该道路找最值得治理的方向；检验同一停车措施在小汽车需求系数0.9和1.0下是否稳健……”发起预览。零调用预检正确冻结双需求、四场景和 `demand_robustness`，但模型初始请求却返回 `needs_input`，追问“优先考察哪个方向/路段”。本次消耗 1 次模型请求、6,670 tokens，**未启动 TranStar 场景**，没有形成可执行计划；原始预览保持 `needs_input`，不续跑。原件与核账见[RC7 预览复核](validation/20260930_rc7_initial_failure.json)。

原因是 `planning-prerequisites-v3` 将“该道路”中的“道路”误当成尚未定位地点，尽管同一原文已经匹配“长江村路”。这使模型有权限走错误追问分支。问题发生在初始许可，不是交通指标或停车措施的实测反馈；RC7 没有验证新传输去重下的反馈规划质量。

## 已实现的有界修正

新任务使用 `planning-prerequisites-v4`：只在**恰好一条**已匹配道路时，将“该道路／这条路”等单数回指视作已定位；无已匹配道路或匹配多条时仍保留定位缺口。即使模型忽略工具菜单并强行追问，新校验也会拒绝引用该回指作为缺口。模型仍负责在新基准后选择具体有向路段。

同时将研究深度升为 `research-depth-v2`，旧 v1 判定函数按原语义只读回放；RC5 原任务用当前代码按 v1 原协议核验仍通过。新规则的原句离线检查返回 `clarification_needs=[]`、`demand_robustness`。修正后的真实初始规划及完整原生闭环仍待单独验证，不能把 RC7 失败改判为完成。
