# RC18 误拒绝与独立判定说明

从 `7285227e` 接续。**整体目标未完成。** RC18 的一次真实尝试在初始规划时被本地文本检查误拒绝，使用一次请求、6,696 tokens，没有启动交通仿真。以下修复和验证均不修改这份原始失败。

## 已真实验证：失败及其原因

RC18 的源码为 `df946787d0e2fd867b8d9d0b7eda4aea06a64d6c`。当次 H1 原文是：

> 七东线停车治理至少一个候选方向的核心耗时低于其无治理新基准，且判定与是否通过推荐约束分开

对应判据是 `core_time_decrease / parking / any / studies=[1]`。H2 单独检验全部约束，H3 检验交通组织或组合相对仅停车的耗时优势，H4 检验组合相对两个单项的耗时优势。模型在 H1 中明确将两项判断分开；v1 检查器仍将说明里的“通过推荐约束”当成 H1 的额外肯定条件，错误拒绝了初始提议。改变措施类型不能解决这次误判，因此没有发起字段修正或第二次请求。

本次使用 `deepseek-v4-flash`，服务返回 `deepseek-v4-flash-0731`，输入 5,908、输出 788、合计 6,696 tokens。原生场景、调度记录、新任务均为零。八份原件逐字节封存，ZIP SHA-256：`70f7dec256f0c72e04a74c49bdc2beaeeed10677dbc9ad0a2d48e713dae924fd`。见[真实失败记录](validation/20260928_rc18_live_checks.json)、[封存摘要](validation/20260928_rc18_raw_snapshot.json)及[原件](validation/20260928_rc18_raw_evidence.zip)。8825 原服务和失败记录保留。

## 已实现

问题口径协议升级为 `bounded-question-wording-v2`。用有限的整句规则识别“判定与是否通过约束分开”“两者分开判定”等说明，仅在检查实际结果主张时将这些独立说明分离；不删除模型原话，不更换事前判据。识别出的原句、来源字段和说明类型随事前解释冻结。

“核心耗时下降，且通过推荐约束”等真实双重要求仍不允许由一个核心耗时指标回答。在肯定条件后面追加“分开判定”，或在说明后添加“但必须可推荐”，不能绕过检查；缺少排队、因果等观测的主张仍不能伪装成已可测。

初始修正回执冻结使用的口径版本，校验时沿用该版本。移除回执和反馈中的版本也不能将新结果降为旧规则。旧 v1 记录仍采用旧实现，RC18 的误拒绝可按原协议精确复现；不事后把失败标为通过。

页面在“口径与适用边界”中展示“独立判定说明”，指出它将问题分开，不代表另一项已经通过。原提问、实际检验问题、事前判据及适用范围并列保留。

这仍是有界文字检查，不是通用自然语言语义认证。任意表述、模型解释质量和本次协议的真实闭环仍需验收。
