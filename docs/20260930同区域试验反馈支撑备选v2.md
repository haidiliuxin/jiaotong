# 同区域试验反馈支撑备选 v2

RC1 的三场景真实运行在第二次选点先产生一次校验拒绝：模型引用了所选 `area_2` 的本次新基准，以及刚执行的 `area_1` 停车 1 级负面反馈，并将未测的 `area_1` 停车 2 级列为暂缓备选。旧 `observed-choice-basis-v1` 只允许备选用本区基准引用，因而要求模型再补一条 `area_1` 基准，产生 15,151 tokens 的修正请求。这是旧校验对已经可见的真实反馈识别不足；原拒绝及修正记录继续按 v1 回放。

## 已实现

新任务使用 `observed-choice-basis-v2`。程序把已试方案的实际修改方向与冻结候选区域、区域实测检查配对，只将**同一区域**的已试反馈关联到未测备选。所选动作仍须引用它自己的新基准；备选可引用自己的基准，或被结构化标明同区域的已试反馈。已试结果只支撑“为何比较或暂缓”，不能当成未测备选的效果。跨区域反馈不能替代备选观测。v1 规则、索引及原件核验分支保留。

模型说明还明确：同一个研究组内的不同治理位置叫不同候选，共用该组同需求新基准；独立研究组才各跑自己的新基准。程序仍提供合法菜单和观测，模型决定所选动作、备选与试验顺序，没有预设治理答案。

## 离线验证

把 RC1 当时**首次被拒的原始工具提议**原样交给 v2 的同一观测索引，现通过选点校验；其已试反馈被严格关联至旧区，不能关联新区。v1 原任务用新源码只读运行完整 `verify_programme --no-write`，包括原 5 次请求、三场景和修正，仍通过。合成边界覆盖所选基准缺失、跨区反馈、同区反馈、索引篡改、旧版复现。621 项 Python 和四组 Node 检查通过；首次完整 Python 运行遇本机 HTTP 连接中断，第二次完整运行通过。相同冻结第二轮输入下，v2 模型输入与工具定义合计比 v1 增加 342 字节，不能据此推算实际 token 节省。

## 真实服务验证

在独立目录只读使用 RC1 的第二轮已完成观测，对新工具做**一次模型请求、零原生场景**。服务响应 `chatcmpl-6abbfe27e2b25fb55024d783`，14,503 tokens；模型一次选定另一区域停车 1 级，列出另一个未测备选，引用所选区基准和首方案负面反馈，通过权限、选点与结论校验。此次实际回复选择的是**新区同区域的备选**，所以不能把它写成真实触发“旧区反馈替代旧区基准”的证明；该边界由上面的原始提议离线重评证明。原 RC1 调度文件 SHA 不变，未启动 TranStar。见[额度增量](validation/20260930_choice_v2_probe_budget_delta.json)。项目留存保守累计为 **93 次请求、792,666 已知 tokens**，仍受 684 次、4,132,560 tokens 累计上限约束，不是完整账户账单。

随后从源码提交 `d299ae49` 构建新的 RC3 包，ZIP SHA256 为 `9a7ba668a897a6d2ca0f7116725d9c7d84eaf46f6185195ab447a079f729abaa`。16,162 文件清单、同机异目录环境与运行后完整性均通过。用该包独立解压副本完成一条新的自然语言任务：新基准、两个实际执行的停车1级候选共三场景／21 个顶层原生模块；4 次模型请求、48,111 tokens，三个决策均一次接受。首候选核心耗时下降 28.5206%，但邻区耗时上升 0.5109% 且毛新增过饱和 2.797 km，超出 0.5% 和 0.1 km 冻结门槛；模型据此换到另一候选区。次候选核心耗时下降 4.6845%，邻区耗时上升 0.00694%、毛新增过饱和 0 km，通过约束并获推荐。第二次选点实际引用了新区基准和首候选实测，以后者解释为什么暂缓旧区未测的停车2级；没有把未测效果当事实。这次**真实触发 v2 的同区域试验反馈关联**，没有产生旧 v1 的选点引用修正请求。独立只读原件核验与公开结论数值／资格复核对这一限定案例通过。见[完整运行复核](validation/20260930_choice_v2_portable_full_live_review.json)和[额度增量](validation/20260930_choice_v2_portable_full_budget_delta.json)。项目留存保守累计为 **97 次请求、840,777 已知 tokens**，不等于完整账户账单。

## 待验证

RC3 的真实任务仅在同机解压副本上运行，物理异机验收仍缺证据。尚未实测真实需求波动、联合区域治理，以及本轮同方向停车1/2级强弱比较；不能将独立候选结果相加、推称全局最优或需求稳健性。原 v5 任务的错误公开结论仍是 `needs_review`，其原件不因新案例通过而改写。
