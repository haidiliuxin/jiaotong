# 固定搜索与反馈搜索的等预算实验

本实验补充此前“反馈多用仿真次数”的可比性问题。区域预先固定为七东线3244→3245、3245→3244和长江村路3240→3239，使用相同核心、邻区、全网指标与约束，不在结果出来后换区域或放宽阈值。

每个小汽车OD系数0.9、1.0、1.1均有自己的新基准。两个策略共享3路段停车2级的首轮，**每个策略最多评估两个治理候选**：

- 固定搜索：第二轮始终试验3路段停车1级，然后按相同约束和目标函数选择候选或保留基准。
- 反馈搜索：只读取首轮结果。未过约束则缩小至1路段；通过但速度/负荷不足则增强到1级；满足停止条件则停止。

第二轮决定在第二轮仿真开始之前写入`decisions.jsonl`。同一个候选若被两种策略提出，只真实计算一次，两个策略各计一次逻辑评估；不把共享计算伪装成独立随机重复。提前停止时实际候选数少于2，会同时报告上限和实际次数，不称每种策略运行次数完全相同。

评价规则相同：核心区时间须改善，邻区时间增幅≤0.5%，全网≤0.1%，邻区新增过饱和有向里程≤0.1km。合格候选优先最小化全网路段行驶时间；无合格候选保留匹配基准。所有结果只说明这个冻结案例和三个离散需求点，不预设反馈策略获胜，不作统计显著性或普遍算法优越性结论。

每个需求最多执行基准、共有首轮和两个不同的第二轮，三个需求的实际场景并集最多12次。标准化时间成本同时包含每种策略相同的基准开销。采用已有多路径增量5轮；禁转联动尚未通过专项验证，因此本实验保持ManageN不变，也不将结果解释为全部道路管理均经过现实验证。

`protocol.json`在首个模型启动前保存，`state.json`记录实际场景和每种策略候选清单，`report.md`在任务结束时形成。核验器重新读结果计算指标、检查需求与参数差异、复算反馈和推荐，并检查第二轮决定的时间早于相应模型启动。
