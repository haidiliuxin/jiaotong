# 正式阅读版构建与核对

报告和操作手册采用通用PDF阅读格式，嵌入图表、中文字体和页码。当前未获得主办方额外的格式、大小和视频时长限制，不把该版式称为已获官方认可的提交模板。

## 发布前的数据检查

`scripts/build_submission.py prepare`要求发布源码已提交，读取已核验研究的状态、协议与选区，逐一匹配核验摘要，再以只读档案模式重新核查原始输入、输出与反馈时序。生成报告不会调用交通模型；“导出核验通过”不能算作新的仿真次数。

旧的`report_region_study.py`同样增加了导出前原始档案核验，不再只依赖历史`passed`字段。导出不会覆盖原实验、核验文件或封存清单。

## 构建步骤

报告构建是可选工具，需要Python、ReportLab、pypdf及微软雅黑字体；模型运行和阅读包完整性检查仍仅使用标准库。先运行全部测试，保存一份只含单次成功运行的日志。使用新的输出目录，不覆盖已封存阅读包。

```powershell
python scripts/build_submission.py prepare --output 成果/提交版本/<新版本> --test-log docs/validation/<测试日志>
python scripts/build_submission.py render --output 成果/提交版本/<新版本>
```

`prepare`核验全部原始档案并记录代码提交，`render`只根据已绑定事实排版。Windows默认读取`C:/Windows/Fonts/msyh.ttc`和`msyhbd.ttc`，可用`--font-dir`明确指定字体目录。渲染后的PDF需使用Poppler等工具导出页面图像，逐页检查表格、中文、地图、页码和阅读顺序。不能用文字提取代替视觉验收。

将最终PDF摘要与已检查页号保存成如下QA记录；只有实际检查全部页面后才能填`passed: true`。排版修改后须重新检查，旧摘要会被拒绝。

```json
{
  "artifacts": {
    "研究报告.pdf": {"sha256": "实际PDF摘要", "inspected_pages": [1, 2], "passed": true},
    "操作手册.pdf": {"sha256": "实际PDF摘要", "inspected_pages": [1, 2], "passed": true}
  }
}
```

页号为结构示例，不是实际页数；须填写各PDF从第1页至末页的完整列表。

```powershell
python scripts/build_submission.py seal --output 成果/提交版本/<新版本> --qa <实际QA记录路径>
python scripts/verify_submission.py 成果/提交版本/<新版本>.zip
```

封存前检查源码与证据副本仍匹配原摘要，PDF包含正确任务及代码版本，QA记录绑定最终PDF。完成后生成目录清单与ZIP，并分别核对。完整性工具拒绝缺失、额外文件、同长度篡改、LFS指针和越界路径。清单不是数字签名。

## 阅读包与完整项目的范围

阅读包含研究报告、操作手册、关键证据、图表数据和源码快照；不含完整模型数据库、原生程序或视频，不能单独启动模型。完整仓库保留第三方程序、南京案例、全部原始场景与历史录像。手册列明五类成果的取得位置和本版尚缺的新视频，避免用体积较小的阅读包冒充完整可运行交付。
