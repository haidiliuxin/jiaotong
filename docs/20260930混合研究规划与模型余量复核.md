# 混合研究规划与模型余量复核

## 真实尝试

同一原始问题要求长江村路至少比较两个不同停车备选，并检验单向组织及组合；最多 7 次仿真，不复跑基准。RC11 包内代码的初始规划及一次有界修正都只提出 `[parking, oneway]` 组合组，没有独立停车组。冻结的 `research-depth-v3` 正确拒绝，2 次模型请求、15,495 已知 tokens、0 原生场景。原问题、失败回复和凭据均未改写。

把研究深度变成显式的结构化研究单元后，下一次源码运行的模型初始规划提出停车组及单向组合组，预留 3＋4＝7 个场景，6 次最低模型请求，得到 `ready`。首组新基准完成后，模型选择停车候选，但首次决策只引用所选 area_1 的基准，漏掉其明确比较的 area_2 备选基准；有界选点修正补齐引用并得到 `accepted`。已完成新基准及停车1级候选共 2 场景／14 个顶层模块。该候选核心耗时下降 23.3087%，邻区耗时下降 0.1821%，邻区毛新增过饱和 0 km，按冻结约束合格。

初始规划恰好占满最低 6 次模型请求；额外选点修正后，剩余额度不足以完成第二停车候选及单向组。调度器将第二次停车选择标为 `blocked`，第二组 `skipped`，整项 `incomplete`。这一个合格候选不能冒充“比较两个停车方案”，也不能冒充单向或组合效果。原件中的两场景模块、输出时间戳、输入差异、范围指标和停车配对对照已只读重算一致；整项未出具通过证明。此运行 3 次模型请求、32,656 已知 tokens。

## 源码修正与边界

新 `complete-study-unit-v3` 把“必须独立停车研究组、至少两项实际候选、当前需求下最少场景数”作为结构化义务同时送入模型上下文及实验工具说明；初始前提失败的唯一有界修正也收到同一义务。它不指定道路方向、停车等级、候选顺序或治理结论，模型仍需自行规划。模型完整混合初始规划已真实返回 `ready`，但其后续完成质量未因此通过。

选点引用修正的运行时许可现在先留足本组其余必需候选／复核及后续研究组的模型请求。对上述恰好 6 次的条件，离线边界测试会拒绝额外修正，从而在错误选点处停止，避免已知无法完成时再运行原生治理。旧记录仍按原选点修正协议回放；这项新余量守卫尚无新的真实运行验证。632 项 Python 检查、旧 RC5 原协议只读完整核验通过。

逐次调用、两个运行的 SHA256、原生核查及保守额度见[证据记录](validation/20260930_mixed_candidate_live_and_budget_guard.json)。当前项目留存累计 **120 次请求／1,115,945 已知 tokens**，授权累计上限 684 次／4,132,560 tokens，不等于完整账户账单。混合候选与单向的完整闭环、模型负反馈后的完成质量及物理异机验收仍待验证。
