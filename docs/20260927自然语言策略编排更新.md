# 自然语言策略编排更新

本轮起点：`d7432c9a`，2026-09-27。用户指出上一版大模型只做情景分类、界面仍要求人工选择场景，要求“大模型模式只有输入框，自动根据自然语言组合不同策略运行”。本轮直接修改产品和调度器；连续环境路线仍暂停。

## 已实现

大模型模式现在是默认入口。操作区只保留工作模式、自然语言输入框及“自动编排并运行”；场景模板、道路、预算、敏感性、硬约束表单和左侧实验列表隐藏。切回规则模式仍可使用这些控件。两种模式草稿分别保留，隐藏表单处于禁用状态，模型模式请求不携带其参数。服务端也拒绝模型请求中的手动覆盖字段。

新的模型工具是 `compose_traffic_plan`。模型读取用户目标和只读路网候选目录，提交目标、组合理由及最多三组实验；不再仅返回一个场景标签。一次规划只调用一次模型，后续自动提交、顺序执行、读取结果均不追加模型请求。实验运行期间，新模型规划会在付费请求前被拦截。

| 模型可组合的措施 | 实际执行 |
| --- | --- |
| 停车治理 | 新基准、治理等级与既有实测反馈；预算内选择或保留基准 |
| 停车＋单向 | 同一组新基准、停车单项、单向单项及组合，对照实际禁行响应 |
| 停车＋禁转 | 已校验转向对应的新基准、停车单项、禁转单项及组合，核验四车型响应 |

停车和单向可在描述限定的道路内根据**新基准**自动诊断目标，不再要求填写方向节点。禁转引用来自当前源路网拓扑：公交保护、绕行、非质心和出口停车条件检查后形成限量候选，模型只能选择这些引用。明确给定的节点不能被模型替换；多个道路范围必须分别说明。不读历史最优方案、不把旧流量或历史收益当新观测。

单向与禁转的联合适配器尚未验证，不能宣称三种措施同时实施。模型可安排“停车＋单向”和“停车＋禁转”两组独立对照；每组单独使用自己的基准和推荐，不汇总为跨适配器的同一收益。施工、信号、公交优先、错峰等必要能力仍应返回待验证，不能由模型编造执行工具。

总预算可直接写在自然语言中，例如“最多10次”“预算控制在十次”。未指定时上限15次，最大30次；默认单需求1.0并复跑基准。程序为各组预留完整对照次数，多余预算最多给停车反馈增加2次；超出总预算时不执行，不偷偷提高预算或删去必需对照。明确需求系数及不复跑指令仍可写入描述。

调度记录包含全部子任务、当前执行项、每组进度和各自推荐。失败时停止剩余实验并标记未执行；无候选结果保留，允许继续另一独立实验。相同令牌不重复执行，源输入摘要在每个子任务的原生锁内再次核对；重启不自动重跑历史实验。右侧展示模型组合理由、预算分配与执行列表；上一版结果标为“历史模型分类”。

## 已检查与待验证

- **229项本地单元测试通过**，JavaScript语法检查通过。新增检查覆盖一般拥堵自动组合、两组合预算、隐藏配置隔离、候选引用、错误/重复/未支持组合、指定方向保护、中文预算、顺序执行、失败停止、无候选保留、运行中不追加模型调用。
- 实际源路网只读检查：长江村路识别成功，可进入停车/单向自动诊断；红景路得到通过拓扑条件的 `4797→5990→5991` 候选。没有运行新原生模块，也没有把这次候选检查记作收益验收。
- 浏览器检查了大模型与规则模式切换、控件隐藏/禁用及草稿保留。见[新入口截图](validation/20260927_natural_plan_ui.png)。
- **本轮新增线上模型请求为0，新增原生仿真为0。** 模型规划结果与多组执行在本地使用明确的测试替身验证；新工具和提示词尚未线上实测。上一版2次模型请求、1327 tokens及3场景/21模块证据仍归上一版，不转记为新编排功能通过。
- 新组合编排的少量真实联调、异机验收仍待验证。没有制作新的便携包，没有更改本机加密密钥，也未恢复旧挑战或连续原型。

示例输入：“长江村路很堵，也有路边停车。帮我比较停车治理和单向组织，自动找合适方向，总共不超过10次仿真。”用户不需要选择措施卡片，模型将形成组合对照并提交给原生执行器；方案有效与否由新结果决定。
