# 研究判据传输去重

## 发现

RC5 双需求任务的模型输入在完整留档之外另有一份传输副本。传输副本已经去掉部分总任务重复事实，但同一条 `research_evidence` 检验仍重复发送：`model_question` 与对应冻结假设相同，`evaluation.interpretation.question` 与该 finding 的 `question` 相同，`evaluation.interpretation.contract` 与同一 finding 的 `test/policies/quantifier/scope` 逐字段相同。这些不是额外证据。

## 已实现

仅当上述字段逐字段相等时，从**模型传输副本**省去重复字段。任务原始输入、完整 finding、校验器读取内容和审计摘要不变；模型仍收到原问题、结构化判据、逐需求观测、负面代价、证据引用及其他解释边界。字段不相等时全部保留。`research_evidence` 与 `programme_evidence` 采用同一条件，后者仅在实际传输时处理。

## 离线验证与限制

按上一提交的原传输函数与新函数，在封存 RC5 的两轮反馈输入上直接比较：第一轮 UTF-8 JSON 从 25,414 降到 23,661 字节，最终轮从 34,243 降到 32,490 字节，均少 1,753 字节。对新传输副本恢复三个省略字段后逐对象等于旧副本；观测、任务门槛及原调度字节未变。测试还覆盖不相等时保留字段，626 项 Python 检查通过。[离线数值记录](validation/20260930_research_wire_dedup_offline.json)保留比较范围。字节节省不能直接换算计费 tokens，也不能证明模型规划质量不变。

RC8 已使用该新传输格式进行真实模型选点和最终复核；完成四个原生场景，但最终因旧 v7 对“**不证明零风险**”的误判而停在 `incomplete`。这证明传输改动进入真实请求，不证明它单独改善计费 tokens 或整项规划质量；详见[RC8 实测](20260930RC8双需求实测与否定证明v8.md)。
