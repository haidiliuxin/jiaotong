# 未定向测试区域：三需求全网安全门槛实跑计划

本轮检查主动稳健停车搜索在**没有该区域定向治理结果参与选点**时能否工作。先冻结选区、任务卡和代码，再启动任何新模型调用；成功、回退、保留基准、缺测与耗费的调用均如实报告。本轮只做单策略迁移检验，不称作等预算新旧算法对照，也不预设一定找到治理措施。

选区由[`select_blind_guard_region.py`](../scripts/select_blind_guard_region.py)使用上一轮已封存挑战任务 `20260922_034228_3141eb` 的**无治理基准**生成。先排除[`challenge_history.json`](../config/challenge_history.json)事前登记的19项历史核心及邻区，再排除上一挑战的高、中、低三处核心及邻区；不读取任何政策场景的指标、比较或推荐。按现有`freeze_regions`固定规则取高密度层第一个合法区域，不根据预期收益挑点。另检查了工作区17份已保存任务范围，所选区域均无核心或邻区交叠；这些额外文件不参与选点规则。

[冻结选区清单](20260923盲选高密度区域选区.json)记录基准原始数组、源码、排除登记与上轮选区的SHA-256，以及全部选择的摘要。244个合法种子中，固定规则选到**兴浦路**种子`1179→1180`，核心三条有向路段`1179→1180`、`1180→1181`、`1181→1180`；核心3条、邻区15条，全网32,060条。该处未被已登记任务当作定向治理核心或邻区；这仍是同一赛事调整案例里的基准驱动选区，不是随机抽样或跨城市迁移。

[冻结任务卡](../examples/parking_robust_guard_blind_high_region.json)SHA-256为`5589609d68da3e88205e20769344305b4d4256004040639776e9711ee2da43da`。采用已发布的`tolerance-v2`与`robust`搜索，停车3级路段试2级起步，需求系数0.9、1.0、1.1分别有无治理基准；最多11场景、两次反馈、预留同输入基准复跑。全网毛新增过饱和有向里程上限0.1 km，原邻区和全网路段耗时等门槛保持默认值。旧挑战任务没有这个新门槛，不能将它的历史结论当作本轮通过证据。

实跑后应核对独立原生程序进程、7模块顺序与零返回码，按各需求基准重算核心、邻区、全网路段Σ(qL/v)及毛新增过饱和；核验事前反馈决定、预算、缺测、统一建议和四类各32,981行原始路段数组的基准复跑。再封存任务、异目录解压只读核验，并把逐候选的成功或失败写进成果入口。若安全门槛没有完整三需求合格措施，统一建议应保留基准，不提高预算、不改点、不改阈值来补正例。

该试验仍不能证明统计意义上的跨区域成功率、现实泊位承接、完整节点延误、异机运行或官方比赛分数；要比较反馈策略与更强固定策略，还需独立的同预算对照。

## 实测结果（2026-09-23）

选区、任务卡与本计划先于求解提交于`50c3ff5b`。真实任务`20260923_075629_706ef0`完成6场景、42次TranStar顶层调用，独立重算、决策轨迹重放、封存及异目录解压只读核验通过；基准复跑四类各32,981行原始数组完全一致。任务档案清单SHA-256为`8ce522a366a407e68947c09601e444bf8dbecdbc21d362a4aef2cb1f25e458a9`。

高需求1.1下，首轮三方向停车2级使核心路段耗时下降22.642%，却使邻区耗时上升25.653%且全网毛新增过饱和0.468 km。智能体缩为`1180→1181`停车2级，核心耗时下降7.104%，邻区仍上升24.720%、毛新增仍为0.468 km。两项都违反运行前冻结的门槛；1.0和0.9需求未进行这两项治理求解，不能视为通过。**统一建议保留无治理基准**，预算剩余5场景。绝对量、逐候选拒绝原因见[复评](../成果/复评/20260923_blind_high_guard/README.md)，完整原始输入输出见[任务ZIP和独立解压核验](../成果/实测档案/20260923_blind_high_guard/README.md)。

这项负结果揭示当前`robust`控制器在单方向措施仍失败时停止，尚未尝试原冻结核心里的其余方向。后续可另行版本化增加预算内回退，但不得修改本任务的原始记录或把尚未求解的替代方向称作有效。本轮不是现有算法对更强固定策略的胜利证据。
