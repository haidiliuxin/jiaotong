## 已实现

新任务采用`referenced-planning-input-v2`，实际发送的 JSON 使用紧凑分隔符。只去掉结构中的多余空格，字符串内部的空格、原始提问、数值、量词、阈值、负面结果、候选目录和证据引用保持。模型仍选择研究与取舍。

每轮记录实际请求正文的 UTF-8 字节数与 SHA256；有界修正的首轮与修正轮分别记录。只读核验在具体语义检查之后核对发送内容，避免通用哈希错误遮住范围、未来结果等具体问题。协议在新基准前冻结；旧 v1 及无协议记录继续使用原序列化方式，执行后不能切换。

**排查更正：**完整留档中的`initial_hypotheses`与`programme_hypotheses`虽有重复，实际发送层已省略多数重复判据。最初尝试只扩展留档副本引用，在本例实际请求中没有节省，因此未保留该改动，也未把留档体积差计作优化成果。当前新增节省来自实际发送序列化。

### 结构通过，独立语义复核仍为 needs_review

模型选择原三方向从停车1级减弱为2级；暂缓备选为同1级缩至两方向。它保留核心改善与推荐资格的区分，正确引用邻区0.5%和0.1km门槛，H2仍未获满足。

但研究假设包含原话：

> 换方向候选（area_2）因与已试不同需求未配对，暂缓。

实际参照需求为1.0，六个area_2候选计划需求也全部为1.0；输入两组换区关系的`matching_demand`均为true。这些候选尚未执行，不能据此说它们使用不同需求。这个错误影响暂缓理由，所以仍不能判定规划解释质量通过。

原话保持。一次随机回复既不能证明压缩修好了语义，也不能证明压缩造成这个错误。本次无重试、无新原生，不能将所选2级与旧任务已测2级拼接为新闭环。
