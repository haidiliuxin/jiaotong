# 泛化拥堵请求的禁转目标修复（2026-10-04）

## 触发问题

用户原始请求为 `帮我治理一下环洲路的拥堵情况`（记录中保留末尾换行）。
原规划记录 `preview_4e29c32208bf4f3799a444bb4ef46315` 中，模型自行加入了“停车＋禁转”研究，
但把禁转目标写成 `auto`，未选择当前路网已校验的转向引用。校验阻止了执行，且普通错误类型没有进入已有的一次初始规划纠正流程。
该请求有效；问题出在模型输出与错误处理，而非用户缺少节点信息。原失败记录保留，未启动仿真。

## 修复边界

- 对用户原句不含禁转、转向或微循环等转向术语的泛化请求，模型自行添加的无效禁转目标进入已有的有界纠正流程。把原请求、校验失败和当前可用转向引用交回模型，最多再请求一次。
- 模型可重新选择合法目标或合法措施。程序不替模型指定节点，也不自动删除方案；第二次仍不合法即停止。
- 用户原句明确提到转向，包括要求禁转、否定禁转或指定转向节点时，保留严格停止边界，不能通过这一纠正机制撤销用户条件。
- 保留原始失败记录、第二次输出、请求数和用量；纠正请求计入原有总预算。未通过规划校验前不执行原生仿真。
