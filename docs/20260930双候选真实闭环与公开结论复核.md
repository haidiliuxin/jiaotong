# 双候选真实闭环与公开结论复核

本阶段沿用明确要求“比较至少两个不同停车治理方案”的同一自然语言案例，依次核查模型选点、实际原生执行、负反馈后的转向、最终结论与文字口径。每次运行均使用新目录和新基准；没有改写或拼接旧失败任务。

## 已实现

- 单研究组模型输入只有在总任务检验与本组检验逐项相同的情况下，才省去发送给模型的重复副本。冻结输入与审计摘要继续保持完整；上次失败的第二决策输入按当前代码约由 36.8 KB 减至 28.8 KB，实际新运行首次决策输入为 10,287 tokens、第二次为 13,460 tokens。
- Windows 控制台日志采用 ASCII 转义输出；权威 `events.jsonl` 仍为 UTF-8。控制台不支持字符或输出流断开不能中断已经保存的模型决策。
- 新 `measured-conclusion-v6` 以冻结的非负毛新增里程、模型剩余额度和停车等级顺序，对明确的公开说明作有界检查。旧 v5 记录仍按 v5 核验；新检查不声称能理解任意自然语言。旧记录的读取视图另列独立复核结果：发现冲突时以结构化实测值为主，隐藏有误的总任务摘要并标记待核对，不修改原调度和报告文件。

## 已离线验证

618 项 Python 测试和四组 Node 检查通过，覆盖 GBK 严格编码、断开的控制台、重复证据去重、旧协议、v6 三种类型化错误、只读页面呈现和便携依赖。用新代码只读重核旧 v5 完整运行仍通过，未重写原记录。把该运行最后回复的副本按 v6 离线重评，精确得到摘要里程符号、模型额度和停车强度三项错误；这是**新口径离线检查**，尚无 v6 真实服务验收。

## 真实运行结果

第一项运行在 `study_depth_workspace_20260930_01`：新基准与首个停车 1 级真实完成，各 7 个顶层原生模块。模型第二次决策首次漏引备选区域基准，一次付费修正补齐引用并保留原选动作，校验通过。然而包含 U+2212 的公开决策在输出到 GBK 控制台时触发 `UnicodeEncodeError`；第二治理未执行，原任务 `failed`。共 4 次请求、47,214 tokens。事件文件中错误字符位置与异常位置一致；原件保留。

第二项运行在独立的 `study_depth_workspace_20260930_02`，代码来源 `e8c736f1`。模型一次初始规划、两次选点、一次最终复核及一次有界最终修正，共 5 次请求、62,464 tokens；三个原生场景、21 个顶层模块完成。首项 `parking_1` 是环洲路候选区三个有向路段停车 1 级，固定核心耗时下降 28.5206%，但邻区耗时增加 0.5109%、毛新增过饱和 **2.797 km**，超 0.5% 与 0.1 km 门槛，未获推荐。模型读取该负结果后选另一候选区两个方向停车 1 级，`parking_2` 核心耗时下降 4.6845%，邻区耗时增加 0.00694%、毛新增过饱和 0 km，通过约束，结构化推荐为 `parking_2`。
