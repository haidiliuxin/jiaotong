# 同预算挑战 v3：车型缓存文件的有界原输入恢复

前三次挑战均保持失败状态。v1 两次分别遇到 `Rwm_car.dat` 和 `volume_car.dat` 打开错误；v2 虽使此前失败的 `case_002`、`case_006` 完整通过，却在完成 9 个物理场景后，于 `case_007` 遇到其协议未涵盖的 `Rwm_motor.dat`。三个失败输入各自在独立目录、同措施同需求下完成七个原生模块，因此已知输入不是确定性不可解，**原生故障根因仍未知**。旧任务和诊断输出不拼接为正式成绩。

本版仍直接使用 v1 的区域排除登记、三层选区、固定全单方向网格和反馈回退控制器，以及 0.9／1.0／1.1 需求、每区每臂 16 个逻辑场景、最多四候选、全网及邻区硬约束。控制器、任务卡、历史排除集合和政策评价均未根据三次失败任务的治理结果修改。由于已观察部分治理输出，本版是执行可靠性修订，**不能再称完全盲测**。

唯一规则变化是将可识别的原生文件打开故障，从 v2 的两种小汽车缓存文件，扩到成功原生场景中实际存在的十个 `cache/(Rwm|volume)_(bus|car|motor|taxi|truck).dat` 文件。仍须同时满足：`M6AssignVehicle.exe` 退出码 1、前三模块成功、错误文字指向**本场景自身**的唯一允许文件、场景输入未变。每个逻辑场景最多额外尝试两次，整任务最多 20 次。失败尝试原字节保留在 `native_attempts`，重试从原案例重新生成同名场景并比较全部执行前输入摘要；失败没有可用于控制器的观察结果，额外原生调用单独计数。其他错误、超限、输入变化或独立审计失败立即终止。

实现及测试应先提交，再运行 `python scripts/benchmark_guard_resilient_v3.py`。只有任务完整完成、严格审计重算原始数组与决策时序、封存清单和导出均通过后，才比较两臂。本协议提高的是间歇性原生故障下的可完成性，**不是治理效果或比赛得分的直接增益**。若再次中止，原样保留失败并诊断，不以部分结果声称胜出。
