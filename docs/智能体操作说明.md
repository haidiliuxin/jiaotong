# 路策交通仿真智能体操作说明

程序提供大模型自主规划和规则模式。大模型模式需要在“API 设置”配置地址、接口类型、模型和密钥；规则模式不需要 API 密钥。程序读取数据、生成治理参数、启动 TranStar、校验结果并保留实验记录，模型模式还会根据新观测选择实验和后续研究。

## 2026-09-28 当前大模型入口

当前源码服务为 `http://127.0.0.1:8823/`，直接在自然语言框描述交通问题，不需要手动选择场景。Token Rhythm 使用 `https://tokenrhythm.studio/v1`、`chat_completions`、`deepseek-v4-flash`。密钥仅在当前 Windows 用户受保护配置中保存，不随源码或便携包提供。

初始方案会先检查研究范围、预算和原问题的检验方式。若只存在可修正的检验对象冲突、预算也足够，系统可请求模型补交一次字段选择；模型不再重述整份方案。界面显示哪些假设被修正，原问题和其他安排保持，第一次失败及第二次用量均保留。所有初始修正共用一次机会，并计入每任务默认六次模型请求上限；修正失败后停止。

“已生成规划”只表示方案可进入执行校验，不代表取得交通效果。新基准、模型选点、实际措施对照和逐项反馈尚未完成时，不把任务标为完成。当前完整真实闭环和物理异机仍待验收；最新真实 RC17 尝试失败，不能把历史实测结果拼成新版本通过。详情见[当前事实入口](../项目事实基线与新对话入口.md)和[RC17失败与字段修正接口](20260928RC17失败与字段修正接口.md)。

下面保留规则入口和历史验收说明，相关日期与运行结果按各自版本理解。

当前普通执行入口支持停车干扰治理、单方向禁行与停车组合、显式单转向与停车组合及小汽车需求敏感性。施工、公交优先、信号、错峰和未指定转向的旧微循环任务返回待验证条件，详见[场景对照](草案场景实现对照.md)。

首次实跑可使用 `python -m traffic_agent run --task examples/parking_quickstart.json`：4场景，包括基准、2级停车、反馈候选及基准复跑，不包含需求敏感性。完整停车需求实验继续使用 `examples/parking_agent.json`，禁转完整组合使用 `examples/turn_access_grid.json`。

## 2026-09-19 新入口与推荐版本

推荐使用项目根目录的 `.\start.ps1` 启动大地图（默认8769端口），`.\start.ps1 -Mode check`检查环境，`.\start.ps1 -Mode run`新建4场景真实验收。详细故障处理、进程级代理设置和另一台电脑验收见[统一启动说明](统一启动与异机验收.md)。下方传统命令仍可使用。

网页新任务默认采用 `tolerance-v2`：极小指标差异视为近似相同，再优先少措施。任务卡在计算前显示并冻结规则；未指定版本的旧JSON继续按旧规则执行，历史结果不会被重写。算法决策栏可查看旧任务的原冻结建议和新版只读复评，以及差异明细、对应地图。规则不是统计显著性检验，详见[参数依据](参数依据与决策容差.md)。

最新验收为2026-09-19的4场景28调用和104项测试，见[优化验收](../成果/20260919优化验收.md)。

## 环境和启动

- Windows，Python 3.12。核心程序、网页服务和测试只使用标准库。
- 保留仓库内完整 TranStar 软件与南京数据库；若通过 Git 获取，需要先 `git lfs pull` 下载实际二进制。
- 程序默认读取 `南京市案例数据库/南京案例/基础路网`，首次运行从 `方案1流程验证/runtime` 建立新的独立计算环境。必须满足原软件的试用授权条件。
- 在仓库根目录运行以下命令。路径均由项目目录推导，不要求固定在 `F:/ITS比赛`。

```powershell
python -m traffic_agent check
python -m traffic_agent serve
```

`check`现在同时检查源数据和所需程序，识别尚未下载的Git LFS指针。按任务检查新接口时使用：

```powershell
python -m traffic_agent check --task examples/turn_access_grid.json
```

硬禁行及显式禁转任务还检查Vehicle1固定版本、四种原生车型程序和PATH中的MinGW `gcc -dumpmachine`。依赖不全返回码2并列出原因，不创建实验或启动TranStar。`preflight_passed=true`只表示这些依赖检查通过，能力状态和真实模型响应验收仍分别判断，授权是否有效由原软件启动检查决定。

打开 <http://127.0.0.1:8765>，填写需求和约束，点击“生成任务卡”查看实际执行参数，再点击“开始真实仿真”。工作台只监听本机，不是供互联网访问的服务。

运行期间可以关闭浏览器标签页，后台 Python 进程仍会继续。若关闭整个运行终端或终止 Python，计算可能中断；此时应检查日志和实际进程，不能将记录中的 `running` 当成任务仍在执行的唯一证据。

相同计算环境使用操作系统文件锁，一次只允许一个完整任务；锁随进程退出释放。请勿手动修改正在使用的 `智能体实验/runtime/files/runinfo_vc6.txt`。

## 命令行方式

```powershell
# 仅检查能力、任务和依据，不运行仿真
python -m traffic_agent plan --task examples/parking_agent.json

# 完整区域停车治理、反馈、基准重复和0.9/1.1小汽车需求敏感性
python -m traffic_agent run --task examples/parking_agent.json

# 指定有向路段
python -m traffic_agent run --task examples/single_link.json

# 可选全网毛新增过饱和安全门槛：本例只测需求1.0
python -m traffic_agent run --task examples/parking_network_guard_quickstart.json

# 查看各草案方向是否已支持
python -m traffic_agent capabilities
```

每次真实任务生成独立目录 `智能体实验/jobs/<时间_随机编号>/`，不会覆盖历史任务。每次完整模型序列通常需要约2至3分钟，具体以本机日志为准；默认任务可能需要8次或更多仿真。

通过 `--source '其他场景目录'` 指定同格式案例，`--root '其他实验目录'` 指定输出目录。输出目录不能放入源场景内部。其他案例必须通过字段、维数和分配配置检查；目前不承诺未经验证的软件版本或不同分配算法直接可用。

## 自然语言与任务卡

自然语言入口是公开规则模板，不是通用大语言模型。推荐：

```powershell
python -m traffic_agent plan --request '分析停车拥堵；路段：七东线；最多治理1条；需求系数：0.9,1,1.1；预算：8'
```

支持 `道路：名称` / `路段：名称`、`最多治理N条`、`需求系数：0.9,1,1.1`、`预算：N`、`不做敏感性`、`不复跑` 等模板。复杂约束应写入 JSON，任务卡中未表达的自由文字不应当作已经实现的控制条件。网页显式表单参数优先于文本模板。

| 字段 | 含义 | 默认值 |
| --- | --- | --- |
| `scenario` | 场景：parking/circulation/oneway/construction/transit/signal/staggered | parking |
| `road_name` | GEOM 中精确道路名，未填写则自动选点 | null |
| `links` | 指定 `[起点,终点]` 数组，须通过对应场景规则；显式禁转时只能等于出口路段 | 空数组 |
| `turn` | circulation专用：`[进口节点,路口节点,出口节点]`，触发已开放的新状态图完整组合；每个任务仍须通过实际响应与指标检查 | null |
| `max_links` | 最多治理有向路段数，1至10 | 3 |
| `max_runs` | 整个任务最多真实场景数，含基准、重复和敏感性 | 10 |
| `max_feedback` | 基准需求主实验的最多反馈候选数，0至3；每个额外需求水平另允许1个总预算内的回退实验 | 2 |
| `demand_factors` | 小汽车OD系数，必须包含1.0，最多3个 | 0.9、1.0、1.1 |
| `repeat_baseline` | 重新运行同输入基准 | true |
| `neighbor_hops` | 在有效机动车网络上展开的无向邻域跳数 | 2 |
| `target_speed_kmh` | 用于反馈增强实验的核心区速度参考阈值 | 25 |
| `max_neighbor_time_increase_pct` | 邻区行驶时间容忍增幅 | 0.5% |
| `max_network_time_increase_pct` | 全网行驶时间容忍增幅 | 0.1% |
| `max_new_oversaturated_km` | 邻区新增过饱和有向里程上限，按新增总量而非净变化核算 | 0.1 km |
| `max_new_network_oversaturated_km` | 选填：全网毛新增过饱和有向里程硬上限；超限撤回候选，网页“影响范围与约束”中可填写 | 不设置，沿用原规则 |
| `module_timeout_seconds` | 单模块超时上限 | 900秒 |

所有阈值是实验假设，应在正式实验之前固定。停车改善至2级与1级是离散参数情景，不代表现实执行成本或容量百分比。

全网毛新增上限是2026-09-23后的可选功能，[便携主程序v5](../成果/便携主程序/20260923_v5/README.md)已包含并完成新任务实跑验收。已封存的v4便携运行包不包含它；若使用v4，请勿把该字段写入任务卡。

显式禁转可用`转向：4797→5990→5991`或三节点`->`语法生成任务卡。完整13场景验收后，可使用`python -m traffic_agent run --task examples/turn_access_grid.json`执行，需要PATH中的MinGW `gcc`。每个需求4场景加基准复跑，三个系数需13次，`max_feedback`不改变预定组合。不带`turn`的历史任务保持原默认分配诊断流程，不能把两种基准混算收益。协议和边界见[禁转完整组合实验协议](禁转完整组合实验协议.md)。

## 智能体如何决定下一步

1. 新建基准并真实运行；仅接受新生成的四类结果和管理修正容量。
2. 根据道路类型、停车类别、有效流量、速度、饱和度和长度筛选瓶颈。自动选择种子及其邻域内有限候选；指定道路不满足条件时不偷偷更换区域。
3. 固定核心、邻区、全网三组有向路段。即使后续缩小治理范围，也保持原核心区评价口径。
4. 首轮将入选路段停车类别改为2级。邻区/全网约束或核心收益未通过时缩小治理范围；通过但核心速度或管理修正负荷仍需改善时，试验1级治理。
5. 按固定规则保留所有候选并选择合格方案；没有合格方案时推荐保留基准。达到预算、反馈轮次或没有新候选时停止。
6. 每个额外需求系数运行独立无治理对照与同一推荐措施，不把0.9需求方案直接与1.0需求基准比较。
7. 复跑一次同输入基准，核查速度、流量、软件V/C、时间四类数组逐项一致。
8. 若推荐措施在某个额外需求水平不满足约束，利用剩余预算缩小治理范围，重新与该需求的匹配基准比较。仍不合格或预算不足时，在该需求下保留基准；不把原推荐包装成适用于所有需求。

可对仍有预算的已完成历史任务追加此项反馈：`python -m traffic_agent adapt --job '智能体实验/jobs/任务编号'`。该命令拒绝运行中或失败任务，并检查保存基准的输入及结果是否与原记录一致。

## 结果与追溯

每个任务包含：任务卡 `plan.json`、状态和结果 `state.json`、时间线 `events.jsonl`、候选 `diagnosis.json`、固定范围 `scopes.json`、模型场景、参数差异、真实进程日志、`report.md`、`report.html` 和 `metrics.csv`。

Git克隆不保留原运行时间戳。已有`archive_manifest.json`的任务使用`python scripts/verify_experiment.py 智能体实验/jobs/<任务编号> --archive`复核复制后的内容和语义；原运行目录仍用默认严格检查，成功后可加`--seal`生成清单。方法和已实测范围见[跨目录核验说明](实验档案跨目录核验.md)。

状态为 `failed`、`needs_validation` 或 `no_candidate` 的任务不能作为成功治理实验。成功进程退出不等于结果有效，程序另检查输出生成、有限值、长度、输入一致性与需求进入分配的证据。

`completed`也只表示实验结束，最终推荐可以是`baseline`。微循环验证入口、S0/S1/S2/S3协议、禁转响应的失败判据和公交补充审计见[微循环验证说明](微循环验证说明.md)。首轮旧微循环实验没有通过禁转响应检查；普通`run`只开放明确`turn`的新状态图流程，旧流程仍未开放。最新结果见[禁转完整组合结果](禁转完整组合结果.md)。网页“载入禁转组合任务”填入红景路、三节点转向、单路段核心及13次预算，生成任务卡后再运行。

最终 `Assign_car.od` 是软件内部末轮矩阵，本机基准总量约为输入的1/15，不能当作全程仅加载1/15需求。Vehicle1硬闭边模式额外保存四车型完整五轮矩阵，逐单元核验5/15、4/15、3/15、2/15、1/15及六位小数序列化精度，再核对累计矩阵；普通停车历史记录若没有分轮快照，仍只使用最终缓存的跨需求比例，不补造历史阶段证据。

## 图表导出（可选）

核心程序不依赖绘图库。需要导出可用于研究报告的图表时：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-viz.txt
.\.venv\Scripts\python.exe scripts/plot_experiment.py '智能体实验/jobs/实际任务编号'
```

只接受 `completed` 任务，输出 PNG 和 SVG：区域基准/治理速度示意、核心/邻区/全网指标对比和匹配基准下的需求敏感性。区域图是节点直连拓扑，不冒充真实道路曲线或地理底图。

## 常见问题与检查

单向与停车完整组合目前使用专用验证入口：

```powershell
python -m traffic_agent oneway-trial --task examples/oneway_changjiang.json
python scripts/verify_experiment.py '智能体实验/jobs/实际完成任务编号'
python scripts/plot_experiment.py '智能体实验/jobs/实际完成任务编号'
```

任务默认需要每个小汽车需求系数4次模型场景加一次可选基准复跑；三个系数且复跑共13次场景。只允许一个待关闭方向，双向停车对照要求max_links至少2。输入道路/方向在新Vehicle1基准中重新检查，不通过即停止，不换研究对象。分配参数与默认停车任务不同，报告分开解释；不能比较两个程序基准的差异作为政策收益。

当前专用入口使用硬闭边适配v2，需要PATH中的MinGW `gcc`。它在任务自己的`runtime/`编译调用包装器，保留原版车型求解器和软件启动检查，Python环境参数仅传递给本次子进程。普通停车入口不需要gcc。生成的私有runtime不提交Git，可由已版本管理的原软件和包装器C源重新建立。

每个场景额外保存`bridge_runs/<场景>/`下四车型各五轮的转换前原始图与阻抗、原生输入、原生输出及映射结果。场景结束时自动核验，缺少20次完整调用、改变保留边阻抗或OD、最终流量无法由原生分轮结果累加时，任务立即失败。外部核验命令也会重新读取这些文件；原有未使用该适配的历史实验按其原配置核验。

该入口完整计算S0/S1/S2/S3，在各需求内核对禁行响应、核心/邻区/全网约束并选择或退回基准，额外要求全网耗时改善。主方案稳健性与条件换方案分别报告。图表导出为完整需求组合及条件推荐两组PNG/SVG。硬闭边v2完整13场景验收通过后，普通run及网页现可发起单方向禁行与停车组合。网页“载入单向组合任务”会填入长江村路、关闭方向3237→3236、双向对照和13次预算；先生成任务卡即可核对。文本支持“方向：3237→3236”或ASCII箭头“->”，只允许一个关闭方向。完整单向网络仍需专项验证；显式禁转使用另一套已验证状态图流程，不能混用；详见[最新验收结果](硬禁行完整组合结果.md)。

| 现象 | 处理 |
| --- | --- |
| 程序仍是LFS指针或缺失 | 在仓库执行 `git lfs pull`，检查软件文件完整性 |
| 另一个任务正在使用环境 | 等待实际运行进程结束；不要仅删除锁文件强行并发 |
| 超时或模块报错 | 查看任务 `logs/<场景>/`；适配器只结束自己的模型进程树，不终止其他工作 |
| 数据维数、字段或候选校验失败 | 对照任务卡和源场景修正输入，不跳过校验拼接结果 |
| 新输出缺失或旧结果残留 | 本轮失败；不要用历史文件替补，先查模块日志 |
| 时间文件存在极大值 | 不汇总TimeLink为全系统总旅行时间；使用明确口径的速度、行驶时间消耗与过饱和里程 |
| 强治理有局部收益但周边超限 | 查看被淘汰原因、缩小范围或使用温和方案；不要临时改阈值掩盖结果 |

执行自动检查：

```powershell
python -m unittest discover -s tests -v
python scripts/verify_experiment.py '智能体实验/jobs/实际完成任务编号'
```
