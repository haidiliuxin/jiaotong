# 前瞻区域对照与复现

本轮实现日期：2026-09-22。研究用于检验同一赛事调整案例内的区域迁移，以及相同预算下固定搜索与实测反馈的差异。它不替代另一台电脑或另一套数据库的重新求解。

## 三类证据分开查看

- `scripts/benchmark_regions.py`：真正调用已有 TranStar 原生模块，创建新的研究目录。
- `scripts/verify_region_study.py`：从原始输入、输出、日志重新计算指标并重放决定；不求解交通模型。
- `scripts/serve_region_study.py`：只读地图和对照界面；不运行模型，不修改档案。

先在仓库根目录按 `.\start.ps1 -Mode check` 检查环境。运行研究需要原软件的正常授权；统一启动检查不能代替授权和真实模型响应。

```powershell
.\.venv\Scripts\python.exe scripts\benchmark_regions.py
```

新任务写入 `智能体实验/studies/<任务ID>/`，不会覆盖此前任务。运行器持有与普通智能体相同的模型锁；前端查看不占模型锁。开始后请保持运行算法文件和原生程序不变，末尾会核对其哈希。研究期间改写这些文件会让任务报错，而不会冒充按原协议完成。

## 事前固定的规则

1. 先保存协议、输入摘要、代码快照、程序哈希及四个历史区域的排除范围，再计算新的需求1.0基准。历史区域为停车主实验、环洲路迁移、红景路禁转、长江村路单向实验。
2. 沿用停车候选条件：城市2/3类道路、停车3/4、长0.1–1.5 km、流量≥500、1＜软件V/C≤4、速度＜40，排除匝道和无意义路名。使用**完整候选集合**，界面前30条展示限制不参与选区。
3. 每条候选依次作种子，从其2跳邻域按基准qL/v补足最多3条核心。最终核心及其2跳邻区与登记历史范围不相交；相同核心集合仅保留节点编号最小的种子。
4. 密度为最终范围内合法候选的有向长度占有效道路有向长度的比例。不同密度取值排序，第i项进入 `floor(3*i/n)` 层；同密度不拆分。按高、中、低顺序，在每层按种子节点编号选取首个与已选范围不重叠的区域。没有合法候选的层保留空缺，不按治理结果换点。
5. 在任何治理仿真之前保存完整候选、全部种子及冻结范围，再补齐0.9和1.1需求基准。所有治理严格对照同需求基准。

这里的密度是本案例的候选停车问题密度，不是现实停车占道率、人口密度或普遍的高低区域分类。选区仅使用新基准，没有看过本轮治理结果。

## 为什么预算公平

每个区域的每个策略最多10个逻辑场景：3个需求基准 + 2个治理候选各最多3个需求 + 1次基准复跑。

| 策略 | 首轮 | 第二轮 | 提前停止 |
| --- | --- | --- | --- |
| 固定 | 冻结核心全部停车2级 | 同核心全部停车1级，无论首轮结果 | 任一需求失败，终止该候选剩余需求 |
| 反馈 | 与固定策略相同 | 首轮失败时按该轮联合治理qL/v收益保留前半；全需求通过且仍有瓶颈时才增强至1级 | 相同失败规则；单路段仍失败，或没有增强触发条件，则停止 |

两策略每一轮的下一步决定一起保存，之后才运行或读取该轮结果。反馈生成器只接收本策略之前的观察。联合仿真中的路段收益排序不是单路段因果贡献。缩减措施不会缩小评价范围：只改一条道路后，仍评价原先冻结的完整核心、邻区和全网。

相同措施、需求、输入和程序只实际执行一次，但每个引用策略都计一次逻辑场景。基准也共享；末尾复跑必须新执行。三地区六个策略最多60个逻辑场景，去重后的物理场景最多31个。原生模块每场景7次。未用预算不补给另一策略，确定性复跑不当作独立统计样本。

任一需求失败后，剩余需求明确缺测。只有同一措施在0.9/1.0/1.1全部通过原约束才参与统一推荐。没有合格措施则回退基准；不以最好的单次结果充当统一效果。

## 推荐与代价

原硬约束继续固定为：核心Σ(qL/v)须改善，2跳邻区耗时增幅≤0.5%，全网≤0.1%，邻区毛新增过饱和有向里程≤0.1 km。推荐用事前登记的 `tolerance-v2`，不会根据新结果调整阈值。

额外展示1跳邻区耗时、全网毛新增过饱和、恶化路段耗时增加量和热点，作为本轮风险说明，不追溯修改通过标准。净里程变化不能替代毛新增里程；总收益不能抹掉局部代价。

## 核验及封存

将命令中的任务ID换成实际值：

```powershell
.\.venv\Scripts\python.exe scripts\verify_region_study.py 智能体实验\studies\<任务ID> --seal
.\.venv\Scripts\python.exe scripts\verify_region_study.py 智能体实验\studies\<任务ID> --archive --readonly
```

核验覆盖七个原生进程、退出码及原始输出流、新生成文件时间、输入差异白名单、停车逐行编辑、OD逐元素缩放和模型内部OD响应、全部区域指标和风险、选区重建、反馈时序、共享计费、最终推荐、基准复跑及报告一致性。

场景副本也保留源数据库自带的既有报告；这些复制的DOCX等文件不是本轮生成的报告。本轮结果以任务根目录的 `report.md`、原生日志中 `fresh_outputs` 登记的输出及独立核验为准。便携验证使用新文件时间戳的字节复制件，复制件位于忽略目录 `智能体实验/study_archive_checks/`；核验摘要单独保存并纳入版本控制。

封存后保留文件原样。封存清单用于检查字节传输一致性，不是数字签名，也不能代替独立机器重新执行。算法关键文件须匹配该次运行快照；后续修改算法时应保留相应核验版本，不能悄悄用新规则重解释旧结果。
