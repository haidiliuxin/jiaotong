# 全网风险候选遍历实验计划

已封存的0.1 km 门槛停车任务在三路段联合方案超限后，只试了首个单路段。首个单路段安全且有核心收益，但剩余两个方向未经独立求解，不能断言它最好。本轮只修改**可选全网门槛任务的反馈搜索**：当首轮联合措施的全网毛新增过饱和超过已固定门槛，且预算足够逐一完成所有入选方向、并预留基准复跑时，依原始诊断顺序将各方向的停车2级单独送入 TranStar。全部候选仍按既有硬约束和容差 v2 选择；没有合格候选就保留基准。预算不足时沿用旧缩小范围规则，因此已封存四场景任务仍按旧流程解释。

在运行前固定[六场景任务卡](../examples/parking_network_guard_singleton_scan.json)：停车、三条上限、需求系数1.0、全网毛新增过饱和上限0.1 km、最多六场景、最多三次反馈、同输入基准复跑。预期预算为基准1＋联合候选1＋三个单方向候选3＋基准复跑1，共6场景/42次 TranStar 顶层调用。若首轮不超限、模型失败或选择的路段数不同，保留真实分支，不强求预期场景数。完成后独立核验输入输出、措施、约束、复跑数组和封存记录。

与原四场景任务的比较只能说明多花模型调用后是否找到更好的安全候选，不是等预算算法增益。对新规则的主张限于该案例、该需求系数、该门槛；最终是否改善核心、全网和选优结果以新任务原始输出为准。若三方向均不优于现有方案，保留负结果，不事后更换路段或阈值。跨需求、跨区域和正式评分仍需另作前瞻验证。
