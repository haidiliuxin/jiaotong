# 禁转状态图：原生单轮分配与需求接入诊断

2026年9月8日，新增禁转4797→5990→5991在原生路由图上取得可重放的单轮响应。最新任务`20260908_085731_turn_terminals`完成4次原版小汽车求解，独立转换及流量保持检查通过：拆分基准目标转移量119.208；政策求解图移除该转移，963条物理道路流量发生变化；拆分基准原生全数组复跑精确一致。

这不是原禁转五场景已经修复。原`check_turn_response.py`仍返回1：旧配置新增规则虽进入缓存，最终转向量1019.9前后不变。当前只冻结新Vehicle1基准的**首轮小汽车分配输入（5/15增量）**，119.208不能与旧完整分配的1019.9直接比较。正式微循环入口仍保留验证门槛。

## 为什么先处理图和接入

直接把非质心交叉口替换成进口、出口状态，可以使禁转成为一条可移除的转移边，但还必须保持需求接入和路径阻抗。当前原生模型的`NodeInZone.dat`参与需求接入，不能仅因5990不在`szn.dat`质心列表，就把原节点当成没有出发需求的纯路口。

反例控制`20260908_084513_native_turn`仅从小区成员列表去掉5990对应的内部编号并维护计数，OD矩阵不变：1,600条道路流量改变，最大7.582；前后控制全数组均精确复现。因此新状态节点不能任意加入或替换小区成员。

本次采用独立的出发接入：保留原节点及其小区内部编号，向每个出口状态连接；道路进口只能进入各自状态，不能回到这个出发节点借道绕过禁转。受控节点不是指定质心，当前不处理质心上的禁转。OD、NodeInZone、szn和分配参数字节保持一致。

## 成本拆分与原生求解

对出口道路原成本C，将其分成转移边C/2和实际出口道路C/2；进口道路成本保持原值。从原交叉口出发的接入边也承担C/2。用十进制精确数值拆分，从进口经过交叉口到出口、或从交叉口出发到出口的总成本都等于原道路路径成本。

```mermaid
flowchart LR
    A[进口物理道路：保留原成本] --> I[对应进口状态]
    I -->|允许转移：出口成本一半| O[对应出口状态]
    S[原5990：小区出发接入] -->|出口成本一半| O
    O --> B[出口物理道路：剩余一半成本]
```

在基准保留全部转移（包括本原生裸图中的掉头）；政策只移除4797来向到5991去向的转移。本轮尚未将旧ManageN规则及禁止掉头条件统一加入构图，不能据此声称全路网原有限制均生效。输入图由12,015增至12,025个节点，拆分基准33,011条边，政策33,010条边；多出的30条分别为25个转移和5个出发接入。所有原物理道路仍一一对应，最终读取的是求解器原始边流量。没有修改最终TSD，也没有合成全路网厂商转向表。

## 最新验收证据

独立脚本`verify_turn_terminals.py`不调用构图函数，而是从控制输入重新推导合法边、状态端点、成本、小区编号和输出映射，重新读取各次原生结果。

- 4次原版求解均正常退出，源输入控制逐字节重放；实际文件与调用前后记录一致，只有原生volume新增。
- 所有原道路、允许转移及出发边组成精确预期集合；新编号不冲突，旧内部节点编号保持，FT、TV、出度和number相互匹配。
- 本轮OD、小区成员、质心和其他参数字节不变；道路路径总阻抗精确保持。
- 拆分基准目标转移为119.208，政策图中不存在这条转移。原交叉口出发接入无道路进口，不能成为绕过被删转移的捷径。
- 新增状态节点流量守恒在原生六位有效数字的逐项舍入界限内；基准最大残差0.0004、政策0.0003。
- 5990的出发流量15.641394，对应本轮所在小区出发量除以6个成员得到15.641405，差值落在输出舍入界限内。
- 无治理拆分相对原控制、政策相对拆分基准，全部原节点的净流量变化均在逐项输出舍入界限内；这不是完整逐OD路径证明。
- 基准33,011项原生数组复跑完全一致。无治理拆分仍改变696条道路的流量，最大0.585；因此后续必须采用同构图新匹配基准，不能跨配置归因收益。
