- 最新协议为 `traffic-plan-decision-v2`，执行结果仍为 `natural-strategy-plan-v5`，不改写旧任务、旧回复和封存记录。
- 新增 `planning-scope-v1`：程序向模型明确全案例／已知道路范围、停车和单向的自动选点能力、每个候选的方向数上限，以及给定需求条件下停车对照的最少场景数。空拓扑引用不等于没有自动选点能力；候选是否存在必须等待本次新基准。
- 追问须引用用户原文中的具体位置或明确禁转要求。把已知道路、全网自动选点、数量上限当作定位缺口会被拒绝；学校门口等确实未解析的位置仍可返回待补充。规则核对引用与已解析事实，不宣称已解决所有地理语义歧义。
- 预算不足由实际实验设计计算并显示；不会改写预算、替模型补造实验、强行执行或自动重试。
- Chat Completions 与 Responses 均限制单次并行工具调用；记录结束状态、输入／输出 token 数、工具数及 schema 摘要。未知用量保持未知，不保存原始回复、隐藏推理、请求头或密钥。
- 新增本地只读 `/api/planning-capabilities`。付费验收前比对协议、工具 schema、指令摘要和请求上限；旧服务不匹配时在 POST 前停止。这不是完整源码一致性证明。
- 前端显示执行范围、每候选数量限制、具体阻塞说明及有引用的追问，初始记录保留安全诊断信息。
