# 显式禁转与停车完整组合实验协议

本实验将已通过三场景、四车型完整接口验收的状态图适配接入Agent。任务卡在政策仿真前固定为[turn_access_grid.json](../examples/turn_access_grid.json)，该协议原先从显式试验入口运行，现完整13场景已独立核验，普通`run`及网页开放明确`turn`的新状态图流程。历史任务卡及政策前协议保留原样。

```powershell
python -m traffic_agent plan --task examples/turn_access_grid.json
python -m traffic_agent circulation-trial --task examples/turn_access_grid.json
python scripts/verify_experiment.py 智能体实验/jobs/<本次任务编号>
```

任务指定红景路4797→5990→5991，出口5990→5991为停车对照核心。指定路段必须是有效机动车道路、停车3/4类且名称匹配，转向必须通过原有公交保护、状态图可达性及绕行上限；不满足则停止，不更换区域。该输入是明确指定的实验对象，不称为自动瓶颈发现。新基准完成后，还要求实际小汽车原生转移量>1，再冻结核心和按两跳计算的邻区。

新建私有Vehicle1环境，五次增量、派生参数3.3；所有场景在指定路口执行同样的既有禁转和禁止掉头。每轮先运行原版参考，再运行适配图，独立检查输入、成本、OD、原节点净流量、状态节点守恒和五轮最终流量累加。原软件检查器保留。新基准来自原案例新副本，不能将之前诊断结果直接冒充本任务基准。

| 方案 | 干预 |
| --- | --- |
| S0 | 同配置无新增治理基准 |
| S1 | 出口停车类别3/4→2 |
| S2 | 仅新增指定禁转 |
| S3 | S1与S2同时实施 |

小汽车需求系数0.9、1.0、1.1，各自建立基准并测齐三项候选；其他车型OD及公交线路不变。最后复跑1.0基准。预算13场景、91次顶层调用、260次适配加260次同输入原版参考。没有用当前推荐替代其他需求点的完整组合，也不声称自适应搜索节省了计算。

候选必须改善固定核心ΣqL/v；邻区耗时增幅≤0.5%、全网增幅≤0.1%、新增邻区过饱和有向里程≤0.1km。另要求全网ΣqL/v严格改善，不能仅凭出口车流减少推荐。S2/S3还要求匹配基准小汽车转移量>1且政策四车型目标转移全部为零；原本为零的车型不作为正流量响应证据。全部ManageN规则必须进入新生成ManageNM缓存。

在通过全部约束的方案中选全网ΣqL/v最低者，平局沿用Agent既有少措施、较温和措施和名称排序规则；无合格候选则保留本需求基准。分别报告条件推荐，以及1.0主方案在其他需求下的固定方案表现；条件换方案不代表主方案稳健。基准复跑要求九类道路数组及原生转移量一致。

运行中每轮证据存入`turn_access_evidence`及`logs/<场景>/turn_verification.json`，政策前保存`factorial_protocol.json`。独立核验重新读取所有原生档案、场景参数、四方案指标、条件推荐和主方案敏感性。完整13场景、91顶层及520原生调用已独立核验；普通入口开放后57项测试通过。真实结果、四组图和局限见[完整组合结果](禁转完整组合结果.md)。

接口范围及先前成功、失败对照见[禁转完整分配适配](禁转完整分配适配.md)。此任务不证明全网既有禁转、全部OD路径或现实交通收益；施工、公交、信号和错峰仍需各自验证。
