# 中密度区域三需求全网风险门槛复验计划

目的：检查已发布的主动稳健停车搜索与可选全网毛新增过饱和有向里程≤0.1 km硬约束，在第二个固定研究区的真实 TranStar 求解中能否形成三需求统一合格措施；保留失败、缺测和计算成本。采用赛事调整后的同一南京案例，不把本研究区称作跨城市或异机样本。

选区来自2026-09-22事前冻结的[三地区前瞻选区](../智能体实验/studies/20260922_015104_1bd73b/selection.json)，文件 SHA-256 为 `a8d634a59db90c33190161b970ec20458c1835e5e212da935c203a50606ab829`。中密度区域种子为74→645，冻结核心三条方向为74→645、645→74、645→782。先前同区反馈研究已找到单方向停车2级的合格措施，所以这是**有历史线索的定向复验，不是盲选或新区域随机验证**；此次不能把过去的治理结果当作新门槛下的通过证据。全网新门槛和全部任务参数见[固定任务卡](../examples/parking_robust_guard_medium_region.json)。

执行前先提交任务卡及本计划，再运行源码智能体。小汽车需求系数0.9、1.0、1.1，各自建立无治理基准；最多11场景、两次反馈、预留同输入基准复跑。旧邻区耗时≤+0.5%、全网耗时≤+0.1%、邻区毛新增过饱和≤0.1 km等约束保持原值，推荐使用已发布的`tolerance-v2`，不根据此次结果改变。智能体依据真实输出记录下一次措施、早停或回退，不能把没有求解的需求写成通过。

完成后用`verify_experiment.py`重算输入、原始输出、固定评价范围、约束、事前决定、预算和基准复跑，再封存及只读档案核验。评价时分别列出全部候选在同需求基准下的核心、邻区、全网路段耗时变化及全网毛新增过饱和里程；只有同一措施在三需求均合格，才报告统一治理建议。若无统一合格措施，保留基准与失败记录，不改路段、门槛或预算来补成正例。历史研究仅可用于同条件原始数组对照，不能作为这次求解调用数。

本轮不做等预算新旧算法对照，不能把单次结果当成新算法优于旧算法或官方得分提高的证明。Σ(qL/v)不含全部节点延误；泊位承接、实施成本、另一台物理电脑及另一套兼容数据仍未验证。

## 实测结果（2026-09-23）

事前任务卡 SHA-256 为 `14c7f72fed4f93e876763a621924b95bda90f2352ec23951d0f5132932362ce1`，在求解前随本计划提交于 `6166e693`。源码任务 `20260923_070135_0f0c08` 完成10场景、70次真实 TranStar 顶层调用，独立核验、封存与只读档案复核通过；预留的同输入基准复跑四类路段数组逐字节一致。封存清单 SHA-256 为 `b8af7f3583b016dbe14d4bd382a5d58b643b9fdf720f7d29096006303c9c3879`。

首轮三方向停车2级在需求1.1与1.0下合格，但0.9下邻区路段耗时上升3.168%、全网毛新增过饱和4.182 km，因此按事前约束被拒绝。智能体根据该失败输出缩为`74→645`单方向停车2级，需求0.9／1.0／1.1下核心路段耗时分别下降6.230%／7.461%／7.678%，全网路段耗时分别下降0.0027%／0.0035%／0.0037%，全网毛新增过饱和均为0；三需求统一推荐该措施。预算余1场景，因不足以覆盖另一候选的完整三需求与复跑，没有追加局部强度试验。
