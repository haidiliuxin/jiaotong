## 真实结果：初始规划仍失败

RC17 来源为 `6c58b300ab2a66913d36b1020d919b453e6cf60e`。它此前的完整性、同机隔离环境及空白页面检查确实通过，但不代表实际规划通过。本次保留六次请求、六个场景的上限，只尝试一个七东线停车与长江村路停车/单向/组合研究的代表性任务。

第一次请求报告 6,669 tokens，把 H2 的“组合相对两个单项的核心耗时优势”错误地设置为检验全部治理类型。第二次报告 8,628 tokens，已将类型改为 `combined`，但把原问题中的“已试措施组合”重述成“已试组合措施”，因此触发原文保护。其余问题、证据需求、判据类型、量词、组别及执行条件没有变化。两次均为校验失败，没有可执行任务或原生场景，没有第三次请求。

这次失败说明修正接口要求模型完整重述方案，产生了可以避免的原文变化。修复应消除重述的必要，而不是通过临时放宽原文校验把失败改成成功。

九份原件已逐字节封存，ZIP SHA-256 为 `c9871bd1896b9e79223d8a0a1d851310f23e1258faf8ae1631d11c67a9400998`。此前 75 份记录和七份原锁保持；加上本次两份尝试，共 77 份记录在开发后再次核对保持不变。见[真实失败核对](validation/20260928_rc17_live_checks.json)、[原件摘要](validation/20260928_rc17_raw_snapshot.json)、[原件 ZIP](validation/20260928_rc17_raw_evidence.zip)。RC17 服务 8822 和失败状态保持，不回写为通过。

## 已实现：只提交字段选择

初始规划协议升级为 `initial-plan-review-v4`，判据修正为 `initial-hypothesis-correction-v2`，新增 `hypothesis-policy-patch-v1`。

- 出现可修正的检验对象冲突时，只开放 `correct_hypothesis_policies`。工具结构仅含本次出错的假设编号，每项为允许的枚举。例如本次结构只接受 `{"H2":"combined"}`，没有方案正文可供改写。
- 模型明确提交字段选择，程序将这些选择应用到内存中的原提议副本，再重新校验完整方案。问题原文、证据需求、量词、研究组、顺序、执行条件及其他说明均由原提议保留；程序不猜选措施。
- 实际字段调用与本地编译后的方案分别记录。回执关联首次失败编号，保留被选字段、实际请求工具/结构摘要和用量，并明确标记方案来源。审计根据原公开提议及字段选择重新构造方案，核对工具结构，不能靠重算冻结摘要隐瞒改写。
- 漏项、额外字段、修改未出错问题、非法选项、重复 JSON 字段、整份方案重写、多次工具调用都拒绝；已发生的请求及用量仍保留。网络失败与本地校验失败分别记录，不自动追加请求。
- 仍与定位/预算修正共用唯一一次初始机会，计入原六次总额。没有可修正范围、预算不足或第二次失败就停止；不放宽交通约束或减少必需对照。
- 页面分列模型选择和“原方案＋本次字段选择”，可以展开原问题和判据；失败、未应用和未执行保持可见。旧 v1/v2/v3 记录按各自原协议核验，不补造字段修正回执。

这项修改解决的是受限工具接口的可靠性。有限文字检查仍不能认证任意自然语言语义，规划、选点、跨组反馈与解释质量仍需完整真实证据。
