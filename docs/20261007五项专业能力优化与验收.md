# 五项专业能力优化与验收

本轮落实初始规划可靠性、多需求稳健反馈、RAG否定语义、结论证据一致性和扩展验收题库。新增能力沿用实际路网菜单、冻结约束和同需求新基准，不通过降低门槛取得成功。

## 改动及边界

| 项目 | 改动 | 证据与限制 |
|---|---|---|
| 初始规划 | `initial-plan-review-v7`允许完整compose工具上下文中的JSON或决策结构错误修正一次；与预算、前提和判据修正共用一次机会 | 原问题、工具schema、执行范围保持原样；两次请求均记账。网络失败、截断、缺失上下文、空白占位和真实信息缺口不自动重试。旧v6不获得格式纠错资格 |
| 规划质量统计 | 新增只读`/api/planning-quality` | 按规划session统计首次ready、纠错后ready、请求数、已知tokens、未知用量和已知耗时。统计包括失败；属于本机历史观察，不能视为受控模型成功率或仿真成功率 |
| 多需求稳健性 | RAG v3停车反馈增加`failed-robust-search-v1` | 同组同措施逐需求列出失败、缺测和备选范围；低需求通过不抵消高需求失败。新候选仍由模型从菜单选择，完整配对由已有执行器保证；不保证存在合格候选 |
| RAG语义 | `curated-knowledge-rag-v3`处理不考虑、不涉及、不需要、暂不实施等否定、并列清单、后置否定、转折与部分双重否定 | v1/v2按旧算法重放，目录与排序权重未改变；仍是有限本地方法摘录检索，不是任意自然语言理解 |
| 结论证据 | 最终协议`measured-conclusion-v18`使用`measured-evidence-support-v3` | 同组同措施必须有全部计划需求的政策结果及匹配基准，才计入合格数；不同组、不同措施不能拼接。阻止明确的未支持稳健、全网最优及无范围“唯一可行”断言；仅识别直接肯定断言，否定结果及“稳健性”名词不冒充肯定结论，未知计划需求保留未知。检查不等于任意语义蕴含认证 |
| 引用支持 | RAG v3增加有限来源一致性检查 | 方法摘录不能证明本次收益；引用指标来源却采用算术平均汇总速度会被拒绝。来源ID存在检查仍保留；任意段落是否完整受到来源支持没有被普遍证明 |
| 扩展题库 | 实现前冻结24道新验收题，覆盖道路改写、否定清单、后置否定、双重否定、指标、单向、施工、公交、信号、错峰 | SHA256为`6127f8718c10461e2d24e18c71d4b012c5a2ef4436169bb71576e5030e3ad323`。旧v2通过17/24，新v3通过24/24，全部检索记录可重算。这是固定验收集结果，不是统计泛化准确率或城市预测精度 |

新增运行包完整性要求检查`evidence_support.py`，RAG v2/v3仍要求失败反馈辅助模块。新协议的证据清单与提示随请求冻结并复核；旧结论v17/v16/v15、初始规划v6、检索v2及更早记录保留原协议行为。

最终离线回归862项Python测试及5组Node页面逻辑测试全部通过。新增回归检查初始格式修正、真实混合决策字段失败、两次格式失败停止、未知用量记账、否定清单与后置否定、方法引用越界、失败需求不被低需求通过抵消、缺少基准、单点不证明跨需求、跨组不拼接、旧协议重放、真实误拒原文及运行包漏依赖。完整固定题库结果在`docs/validation/20261007_professional_acceptance.json`。

## 可复现检查

在仓库根目录执行：

```powershell
python scripts/run_offline_tests.py
python scripts/validate_professional_acceptance.py --output professional-acceptance.json
python scripts/verify_programme.py 20261005_165015_8fd3c0 --no-write
```

验收脚本仅执行本地检索与复核，不读取密钥、调用模型或执行原生仿真。完整模型闭环另用本机已配置的DeepSeek官方接口，原始实验大文件及密钥不提交。

## 未被证明的能力

此前正常需求下合格的单方向停车方案，在需求1.1下失败的证据仍有效。本轮实现更完整的搜索反馈和证据约束，不承诺模型每次都能找到合格措施。真实现场校准需要流量、速度和排队等现场数据；测试通过、确定性复跑和仿真内指标一致不能替代现实精度验证。
