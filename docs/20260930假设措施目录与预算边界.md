# 初始假设措施目录与预算边界（2026-09-30）

本阶段只使用封存的初始规划失败原件做只读分析，未调用模型或 TranStar。原问题、原回复和失败状态保留。

## 原件说明

最新 v10 规划回复安排了独立停车组与单向组合组，原生预算为 7 场景，模型完整研究至少需要 6 次请求。第三条假设的文字问“交通组织（单向及组合）中至少一项核心耗时是否优于本组仅停车”，却填 `criterion.policies=traffic_control`；这一类型只检验单向／禁转单项，不含组合。本地判据在原生执行前拒绝，原件 `validation_failed`、`native_started=false`。影子复制提议，仅把该字段改成 `control_and_combined` 后，全部初始假设判据离线通过；原件没有被改写。因完整研究占满 6 次请求，没有空间再做一次模型字段修正，程序未追加付费调用。

## 已实现

新 `natural-strategy-plan-v8` 将结构化 `hypothesis-policy-family-v1` 目录发给初始模型。目录逐项列出 `all`、`parking`、`traffic_control`、`combined`、`control_and_combined` 对应的实际措施成员，并显式列出相对仅停车优势和原生控制响应检验排除停车自身。实际配对检验也从同一目录取措施成员；模型仍提出假设、研究组和判据，程序不替模型挑治理答案或改写原问题。新工具字段说明指向该目录，侧栏识别 v8；便携清单要求包含新版本所需的目录源码。

## 验证范围

结构化目录和实际检验成员关系的合成检查通过，含 `traffic_control` 不含组合、`control_and_combined` 含交通组织与组合，以及特殊检验排除停车比较基准。637 项 Python 全量检查、四组 Node 检查、旧 RC5 v6 只读整体验证通过；随后针对新增便携清单检查又通过 14 项定向测试。原初始规划失败文件哈希未变。核验数值见[阶段索引](validation/20260930_policy_family_v8_offline.json)。

**仍待验证：**v8 对真实模型初始判据的改善程度、新版完整停车与单向组合实跑、最新便携包及物理异机验收。先前真实任务均未因离线影子检查变成完整通过。项目留存累计用量仍为 127 次／1,186,544 已知 tokens；本阶段新增请求与原生场景均为 0。
