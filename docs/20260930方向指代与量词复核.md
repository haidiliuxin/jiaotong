## 发现与实现

单向选点回复明确说“禁行高拥堵方向3237→3236可将车流导向保留方向”。冻结的 `oneway-direction-v2` 将其后半句误归给前面的方向对，以 `direction_reversed` 拒绝，留下正确的 `incomplete` 状态。新 `oneway-direction-v3` 只在同句明确描述车流**导向另一保留方向**时排除该目的地短语，仍用 v2 检查其余明确的禁行／保留声称。对封存回复仅在内存副本中将协议切到 v3，完整决策工具检查通过；反向禁行、明说保留拟关闭方向的合成反例仍被拒。v1/v2 历史记录照旧回放。这只能证明一次已检测误拒可消除，没有执行单向治理。

独立检查初始假设还发现：H1 原话是“至少存在一个可通过全部原定约束的停车治理方案”，所需证据却要求“两个停车候选均需通过”，冻结判据为 `quantifier=all`。本次两项措施恰好都通过，`supported` 的结果不能掩盖定义漂移。新 `bounded-question-wording-v5` 识别“至少存在一个／至少有一个／存在至少一个方案”等存在量词，以及“两个候选均需通过”等全称证据条件；分别核对原假设、所需证据与结构化量词。封存 H1 在原 v4 下无已检测冲突，在 v5 影子检查出现 `quantifier_changed`；只把判据改成 `any` 又与原证据条件冲突，必须由模型在新初始规划中给出一致表述，不得改写用户原问题或历史回复。v4及更早协议保留。初始规划指令同步明确三处量词应一致。

停车候选选择轮的输入仅对**逐项完全相同**的判据解释作共享引用，并在只有停车选择权限时省略其他阶段的说明；持久化原输入、硬约束、负面结果、引用及阈值均保留。冻结 v9 的两轮输入离线对照，传输内容各少1,542个 UTF-8 JSON 字节，阶段说明各少2,990字节，合计约4,532字节／轮。这是离线字节对照，不能推称服务商计费tokens按同一比例下降。新真实请求的输入tokens分别为6,776、10,994、13,874、14,667、8,860；不能用不同任务的数字反推精确节费。
