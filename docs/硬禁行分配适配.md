# 新增单向禁行的原生路由图适配

2026年9月8日，在长江村路3237→3236、小汽车OD系数1.1的独立诊断中，新增闭边已通过完整分配响应：小汽车1031.92→0、出租车279.18→0，反向仍有车流。三场景、21次顶层模块调用、60次车型分轮原生求解均通过独立核验；无闭边基准与原配置九类数组逐项一致，策略复跑九类数组也逐项一致。

这解决了本次新增方向在诊断流程中的禁行残余。该单向方案仍使固定邻区耗时增加175.2203%、新增过饱和有向里程1.13554km，不符合此前治理约束。该诊断之后的v2已接入智能体并完成整组验收，见文末更新；响应通过仍不能写成推荐该政策。

## 从残余到可重放输入

前一组完整需求实验发现禁行方向在第二轮产生残余，后续轮次没有清除。新的同输入政策复跑`20260908_071807_capture_increment`完成七个模块，四类常规数组与原1.1单向场景逐项相等，并在第二轮输出稳定后保存12个输入及辅助文件。捕获的小汽车该轮流量为0.873942。

直接调用原版`NodeAssignModel_car.exe`，仅使用这些文件即可在约3.5秒逐项复现32,981项原始volume。TV使用内部节点编号，必须通过rnode和n_r重建端点后与FT完整匹配，不能简单把TV当成原节点编号加一。

| 冻结第二轮的单变量实验 | 禁行目标原生流量 | 与控制不同的边数 |
| --- | ---: | ---: |
| 控制：Rwm为9,999,999,999 | 0.873942 | 0 |
| 仅改为10,000,000,002 | 0.873942 | 0 |
| 仅改为1,000,000,000,000 | 0.873934 | 1 |
| 恢复控制并重复 | 0.873942 | 0 |

因此，先前观察到的两个大阻抗值之间不存在足以解释残余的简单阈值切换；更大的有限成本也没有实现硬禁行。这里没有声称已经证明原多路径算法内部产生残余的具体公式。

原始文件见[第二轮成本试验](../智能体实验/probes/20260908_072038_node_cost/verification.json)。以下核验命令应返回1，明确保留未解决配置的失败信号：

## 求解前移除边，而后按端点映射

下一步在原生求解**之前**移除新增禁行边：同步更新边数、该起点的出度、TV、FT及对应Rwm位置，保持节点、OD与其余阻抗不变。原生程序生成32,980项缩小路由图的输出，再按保留边索引映射回完整33k边序；不存在于求解图的边以零表示。原始缩小图输出单独保留，不能用修改既有最终TSD替代这一过程。

单轮试验`20260908_072422_node_pruning`显示原0.873942流量转移到3237→4082→3235：两条替代边分别增加0.874和0.87；3236→3235减少0.8739。四个受影响节点的净流量变化最大约0.004，与原生六位有效数字输出精度有关。这是流量重新分配的证据，但不是全部OD路径守恒的完整证明。

首次完整接入`20260908_073039_hard_access`因隔离目录缺少原版M1-StarNet启动检查而失败，记录保留。随后把原版检查程序及日期文件原样复制到子运行目录，仍执行软件自身检查；没有跳过检查或修改日期值。
