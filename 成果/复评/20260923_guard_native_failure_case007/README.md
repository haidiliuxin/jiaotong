# 原生恢复版同预算挑战：未覆盖的电动车缓存文件故障

原生恢复版任务 `20260923_104406_b479f7` 完成 9 个物理场景后，在高密度区的 `case_007` 因 `M6AssignVehicle.exe` 打开自身 `cache/Rwm_motor.dat` 出错而失败。其 v2 协议只允许 `Rwm_car.dat`、`volume_car.dat` 两种已观察到的小汽车缓存文件故障原输入重试，因此**正确停止，没有擅自扩大规则**。该任务保持 `failed`，9 个局部成功场景不能冒充完整同预算两臂成绩。

独立诊断 `20260923_guard_case007_replay` 用相同停车措施和 1.1 小汽车需求，从原案例重新准备场景。执行前 214 个输入文件摘要与失败场景逐项一致；七个 TranStar 原生模块这次全部完成，产生 32,981 行结果。这排除了该输入必然无法求解的解释，但未确定原生文件打开错误的根因。诊断结果没有拼接进失败任务，也不计作策略观察。

`evidence/` 保存两个任务的关键状态、协议、输入核对和原生进程日志。[manifest.json](manifest.json)列出 13 个证据副本的来源与 SHA-256；完整原始场景仍在本地任务目录。此包只用于故障诊断，不是完整挑战的成功封存、异机复现或官方得分。

据此另行登记了[车型缓存有界恢复 v3](../../../docs/20260923同预算挑战车型缓存恢复v3.md)。它重新启动完整挑战，不复用这里的部分场景；是否完成及两臂效果仍以新任务独立核验为准。
