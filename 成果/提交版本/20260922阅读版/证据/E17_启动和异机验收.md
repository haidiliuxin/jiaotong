# 统一启动与异机验收

2026-09-19。项目根目录提供 `start.ps1`，当前交付环境为Windows和Python 3.12。依赖检查与真实模型验收是两个步骤。

## 在项目目录启动

```powershell
# 只检查依赖、完整程序文件、源数据及输出目录
.\start.ps1 -Mode check

# 启动大地图工作台，默认端口8769
.\start.ps1

# 新建四场景真实停车验收：基准、两级治理、基准复跑
.\start.ps1 -Mode run

# 检查显式禁转所需的MinGW；路径只对本次Python进程及子进程生效
.\start.ps1 -Mode check -Task examples/turn_access_grid.json -CompilerBin C:\mingw64\bin
```

脚本优先使用本项目`.venv`，其次使用Python启动器的3.12版本，最后尝试PATH中的Python并检查版本。打开 `http://127.0.0.1:8769`。端口占用会明确退出，可改用 `-Port 8771`；不会自动结束未知服务。关闭网页并不停止后台，在启动服务的窗口按Ctrl+C停止网页服务。仿真未完成时应先等待任务结束，以免中断原生程序。

若PowerShell执行策略不允许运行本地脚本，可直接使用等价的 `python -m traffic_agent.startup --mode serve --port 8769`，无需改变系统执行策略。请确认这里的python是3.12。

Git克隆的程序若是LFS指针，先安装Git LFS并在仓库执行`git lfs pull`；检查器会把指针、缺失程序和非Windows程序分别报告。不要把“文件名存在”当成完整软件。

停车主线不需要gcc；显式禁转/单向适配需要Windows MinGW gcc。本机已检查`C:\mingw64\bin\gcc.exe`，目标为`x86_64-w64-mingw32`。这不意味着另一个电脑已有相同路径：协作者需安装自己的工具链，使用`-CompilerBin`指向实际bin目录。检查器核对目标，真实任务还须验证包装器编译和四车型原生响应。

启动器只在自己的进程中为127.0.0.1、localhost和::1追加代理绕过项，保留其他代理配置，不修改系统代理和用户环境变量。网页测试使用明确不走代理的本地HTTP连接。浏览器若被外部扩展强制代理，可为本地地址设置例外；脚本不能保证控制独立浏览器进程。

每次启动会保存`智能体实验/startup/<编号>.json`，含时间、Python位置与版本、Git提交、当前Python代码内容哈希、任务卡、模型/编译器检查、输出路径和剩余空间。真实执行另外保存JOB编号、退出状态、模型日志和新鲜输出。检查通过不代表当前授权有效；不修改软件授权机制。

## 另一台电脑的验收记录

**当前仍未获得另一台物理电脑上的真实新版复跑记录。** 同机隔离Python环境与档案复制核验均不能替代异机模型执行。请按以下顺序形成记录，不必先运行耗时较长的禁转案例：

1. 记录机器、Windows、Python、仓库提交与LFS获取情况。
2. 保存`-Mode check`输出及对应startup JSON。
3. 执行`-Mode run`，保留完整控制台输出、JOB目录和失败记录。
4. 运行 `python scripts/verify_experiment.py "智能体实验/jobs/<实际编号>" --seal`，再执行同路径的`--archive`检查。
5. 记录开始结束时间、4场景/28次模块调用、四类数组复跑结果、推荐、报告可读性；逐项标记通过、失败或未做。
6. 若要以禁转为主展示，再运行`examples/turn_access_grid.json`的完整三需求四方案流程，核对13场景、91顶层和520原生调用；停车通过不能代替禁转验收。

模型授权、缺失程序、编译器或输入错误导致失败时，保留错误及日志，不改结果文件伪造成功。完成后将异机验收记录放在新的成果目录，避免覆盖本机记录。
