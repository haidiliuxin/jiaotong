## 2 检查与启动

在仓库根目录执行，检查成功后再启动。

```powershell
py -3.12 -m traffic_agent.startup --mode check
py -3.12 -m traffic_agent.startup --mode serve --port 8780
```

若端口占用，改用空闲端口并访问对应地址，不结束不明进程。Python启动器不可用时，以已安装Python 3.12可执行文件替代`py -3.12`。本机解释器路径为`F:/jiaotong/test-tools/Python312/python.exe`，该路径不要求在其他电脑存在。

可选入口：`powershell -File start.ps1 -Port 8780 -Python C:\实际路径\python.exe`。单向、禁转研究还需在启动命令增加`--compiler-bin C:\实际路径\mingw\bin`；先用相同参数执行check。检查通过不等于授权或模型响应验收通过。

## 3 配置模型

右上角“API设置”中保存服务基址、接口类型、模型和对应平台密钥。本次实测组合为DeepSeek官方、`https://api.deepseek.com`、Chat Completions、`deepseek-v4-flash`；模型名与权限以平台实际可用配置为准。转发服务签发的密钥必须匹配该转发地址，不能与官方地址混用。

保存设置不请求模型。“测试已保存配置”会产生一次服务请求，未保存修改需先保存。Windows用户加密配置只用于本机，迁移后重新配置。密钥不发送到聊天、报告或Git，不在页面回显。

## 4 发起研究

选择“大模型自主规划”，输入位置、研究目标、需求条件和预算，点击“自动编排并运行”一次。系统先检查设计，之后建立新基准；模型基于新基准选择候选，收到结果后决定下一步。仿真期间保留终端和服务，不重复提交相同请求。

本版已经实测的9场请求如下。重新执行将调用模型并产生新仿真，不是免费回看，也不保证获得相同决策。

```text
环洲路停车拥堵治理，检验同一措施在需求变化下是否仍有效，并比较至少两个不同停车备选方案。先建立新的无治理基准，根据首个候选的实际结果选择第二个候选。只做停车研究，不比较停车强度。需求系数：0.9、1.0、1.1；最多9次仿真，不复跑。未找到跨需求合格方案时如实说明。
```

9场由三个新基准和两个候选各三场组成，模型请求单独计数；增加研究组、等级比较或需求条件会增加预算。范围不明确或设计不足时应补充原问题，不通过放宽约束或删除必需场景来强行运行。任务默认模型请求上限7次，有界修正也占预算。

## 5 查看结果

检查总任务和当前研究组的状态、任务ID与已完成场景。单组完成或地图有结果不等于整个请求完成。失败后仍可显示旧实验地图，应以地图的数据来源标注为准，旧收益不属于新请求。

在“规划”中查看模型选择、原始解释、失败与修正；在路网和地图中核对实际治理方向；在评估中比较同需求的新基准与治理，查看核心、邻区、全网及分区代价；日志用于检查原生调用。通过约束不是零代价，也不意味着达到25 km/h目标速度。跨需求建议必须确认同一措施全部计划需求已测且通过。

已完成任务`20261007_010958_039964`有9场、两个候选。第二候选为3107↔3108停车3→2，代表推荐`model_2_demand_1p000`。读取历史记录和刷新页面不应重新发起研究；录屏回看与新运行分别标注。

## 7 故障处理

| 现象 | 处理 |
|---|---|
| HTTP 401或403 | 核对密钥签发平台、基址、模型权限与客户端限制；保存正确配置后另建新任务，保留原失败 |
| WinError 2或依赖缺失 | 执行启动check，核对软件实体、原生程序、编译器实际路径和目标 |
| 地点或禁转目标未通过校验 | 使用当前路网中的道路名；禁转需明确进口—路口—出口或由合法菜单选定 |
| 规划结构失败 | 满足完整上下文条件时系统仅允许一次修正；第二次失败保持未完成，不反复手动重复付费请求 |
| 候选不通过约束 | 查看完整代价和失败需求；允许Agent调整或保留基准，不将其视为程序故障 |
| 有旧地图但本次失败 | 核对实验ID和数据来源，分开查看当前请求与历史结果 |
