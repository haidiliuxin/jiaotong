# 方案一最小流程验证运行说明

本目录保存南京案例的独立工作副本、TranStar 原有计算程序的隔离副本，以及本次流程验证使用的 Python 脚本。目标是验证“读数据—选路段—修改停车参数—运行仿真—读结果—反馈调整”链路。

## 环境与运行方式

- 操作系统：Windows。
- 本次脚本运行环境：Python 3.12，仅使用标准库。
- 软件：工作区已有的 TranStar 城市交通版 V4.8 试用版计算模块。
- 原始案例来源：`F:\ITS比赛\南京市案例数据库\南京案例`。此前压缩包已被解压，本次直接读取此目录，并建立独立副本。
- 仿真方式：调用原软件的模型可执行程序，没有重新实现交通分配模型。
- 需求设置：沿用案例已有 OD；不重新计算人口生成、交通分布和方式划分。
- 分配设置：沿用 `Mparam631.txt` 中的多路径增量加载方法，5次迭代；这是固定迭代实验，不宣称达到网络均衡收敛。
- 公交设置：沿用 `Mparam633.txt`，公交车辆按既有公交线路分配。

`runtime/files/runinfo_vc6.txt` 为程序实际读取的场景路径配置，第一行为 `scenario_dir`，第二行为场景绝对路径。不要在两行之间插入空行，否则程序可能读到空路径并尝试打开 `/data/conn.txt`。使用 GB18030 编码。

该调用方式通过本地程序实跑确认，不视为厂家承诺稳定的公开API。版本更换后需要重新验证。

**同一份 runtime 必须串行运行。** 多个模型任务同时修改场景路径配置会造成任务串扰。本次四组实验按顺序运行。

## 目录说明

| 位置 | 内容 |
| --- | --- |
| `baseline/基础路网` | 新运行的基准场景 |
| `parking_level2/基础路网` | 单一路段停车影响3级调整为2级 |
| `parking_level1/基础路网` | 根据首轮结果补充的1级治理实验 |
| `baseline_repeat/基础路网` | 同输入基准复跑，用于检查结果复现 |
| `runtime` | 隔离复制的原有计算程序、依赖库与配置 |
| `runs` | 每次调用的时间、进程编号、退出状态、标准输出、错误输出和文件更新时间记录 |
| `analysis` | 指标JSON、路段CSV、候选及方案对比 |
| `反馈决策.json` | 首轮观察、追加实验理由与停止边界 |

`baseline` 是固定OD下的新基准，不要求复现案例中历史结果文件的数值；历史文件不作为本次治理效果的对照。

## 脚本职责

| 脚本 | 职责 |
| --- | --- |
| `run_modules.py` | 写入工作副本场景路径，串行调用模型程序，记录日志、退出码、错误标志及变化文件 |
| `analyze_results.py` | 按GEOM顺序关联路段结果，计算指标并筛选停车治理候选 |
| `prepare_intervention.py` | 从基准复制新方案，自动选取候选第一名，仅修改目标有向路段的停车类别 |
| `compare_results.py` | 比较目标路段、固定邻区和全网结果，核对输入差异与OD一致性，输出反馈建议 |
| `verify_results.py` | 核查四组完成记录、输出更新、输入差异和基准数值复现 |

选点及反馈规则是透明的确定性规则，本次由对话中的智能体组织执行；目录内没有集成独立的大语言模型服务或参赛前端。

## 重跑已有实验

以下命令可在 PowerShell 中逐条执行。重跑会更新指定工作场景内的计算结果，并在 `runs` 中新建调用记录，不修改原始案例。若需保留当前工作场景的全部原始输出，应先另存该实验目录。

运行基准的完整计算序列：

```powershell
python 'F:/ITS比赛/方案1流程验证/run_modules.py' 'F:/ITS比赛/方案1流程验证/baseline/基础路网' M3DataRoadNetwork.exe M3DataBusNetwork.exe M3DataTrafficManage.exe M6AssignVehicle.exe M6TrafficLoadLinkVeh.exe M6TrafficLoadNodeVeh.exe M6NodeQueueDelay.exe --timeout 900
```

解析基准：

```powershell
python 'F:/ITS比赛/方案1流程验证/analyze_results.py' 'F:/ITS比赛/方案1流程验证/baseline/基础路网' 'F:/ITS比赛/方案1流程验证/analysis/baseline'
```

创建一个新名称的2级停车治理方案。脚本拒绝覆盖已有同名目录：

```powershell

```

运行新治理方案，必须等待命令正常结束后才比较结果：


## 结果口径与已知限制

1. 路段输出按 `data/geom.txt` 的有向记录顺序关联，核对数组长度。缓存容量按 `cache/FT.dat` 的起终点映射读取。
2. 本次全网评价固定为道路类别1至6、机动车车道数与长度均大于0的有向路段，共32,060条；并非全部32,981条网络记录。每个方案使用同一集合。
3. 平均速度采用 `Σ(qL) / Σ(qL/v)`，长度为千米、速度为km/h、流量为pcu/h。`Σ(qL/v)`解释为1小时分析窗口的路段行驶时间消耗，不包含独立核算的全部节点延误。
4. 软件饱和度 `VCLinkVeh.tsd` 使用 `VolLinkVeh.tsd / CapLinkVeh.tsd`。本次目标路段的该容量分母保持657.143，停车治理改变的是 `cache/CapLinkVehMan.dat` 中的管理修正容量，二者不能混用。
5. “流量/管理修正容量”为另行计算的诊断比值，不冒充软件原生饱和度结果。
6. `TimeLink.tsd` 中存在极大值，包括9,999,999,999。当前分析器对评价集合内大于等于1,000,000秒的记录标记，停止输出该文件的全网时间总和；不通过删除不利记录拼出所谓总旅行时间改善。
7. 邻区采用基准路网中目标两端节点的无向两跳节点集合，再取集合内有效有向路段，排除被治理方向，共27条。该范围用于流程试验，正式研究还需根据走廊和实际影响范围确定。
8. 退出码为0只是程序正常退出的证据，还应检查错误标志、目标结果新写入情况、文件长度和数值。计算进行中不得读取部分结果作为正式比较。
9. 单一路段改善不能推导出全城治理有效。需求敏感性、容量与阻抗标定、停车需求承接、治理成本和多路段组合优化均留待下一阶段。
